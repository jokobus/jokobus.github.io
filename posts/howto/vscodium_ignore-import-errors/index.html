Avoid Python Package Import-Errors in VSCodium or VSCode

📅 31. May 2026 ⏱️ ~1 min read (173 words) #IDE #VSCodium

If you are working with Conda environments, you might notice that VSCodium or VS Code shows “import not found” errors (red squiggly lines) even though your code runs perfectly fine in the terminal.

This happens because the IDE’s Python extension doesn’t automatically know which Conda environment to use for its background linting and IntelliSense. By explicitly setting the interpreter path, you tell the IDE exactly where to look for your installed packages.

How to fix it

Option A) Set default interpreter

In your project root, create a .vscode folder and add a settings.json file inside it. Paste the following configuration, replacing the path with the location of your specific environment’s conda python executable:

{
  "python.defaultInterpreterPath": "/Users/username/miniconda3/envs/my-env-name/bin/python"
}

Option B) Ignore all missing imports

If you don’t want to specify an interpreter and simply want to hide the error messages, you can add this to your settings.json instead:

{
  "python.analysis.diagnosticSeverityOverrides": {
    "reportMissingImports": "none"
  }
}

This tells Pylance/Pyright (the language servers) to stop reporting missing imports as errors, though it won’t help with autocompletion.
