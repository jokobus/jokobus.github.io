Deploy local AI via Ollama, Open-WebUI and VSCode/VSCodium

This guide walks you through installing Ollama on a Linux system, serving it to a strictly local localhost WebUI (ensuring no exposure to the internet), and leveraging your local Large Language Models (LLMs) as an AI Chat Agent and autocomplete engine inside VSCode and/or VSCodium.

Why Run Local AI?

  • No Root / Sudo Required: Runs completely within user space under your home directory.
  • 100% Private & Air-Gapped: Zero external telemetry, no data scraping by third parties, and all inference remains strictly on localhost.
  • Cost Effective: No API subscriptions, token charges, or usage caps.
  • Web Search Extensibility: Open-WebUI can optionally connect to search backends (such as DuckDuckGo / SearXNG) for live Retrieval-Augmented Generation (RAG).

Prerequisites & Hardware Considerations

  • Hardware Acceleration: While lightweight quantized models (1B–3B parameters) run comfortably on modern CPUs, responsive interactive coding and 7B+ parameter models perform best on dedicated GPUs with 8 GB+ VRAM (NVIDIA CUDA, AMD ROCm, or Apple Silicon unified memory).
  • Scope: This guide focuses on a secure, localhost-only developer setup on Linux (Ubuntu, Debian, Arch, Fedora). Native installers are also available for Windows and macOS.

1. Install Ollama

Create the Directory Structure

First, let’s create a dedicated, isolated folder structure inside your local home directory to keep everything organized.

mkdir -p ~/ollama/{bin,lib,logs,models,webui}
  • bin/: Stores the Ollama executable.
  • lib/: Holds necessary libraries and dependencies.
  • logs/: Keeps tracking and server logs.
  • models/: Stores downloaded LLMs (e.g., Llama, Mistral, Qwen).
  • webui/: Reserved for our frontend interface files.

Download and Move the Binary

Fetch the latest standalone Linux binary directly from Ollama and make it executable:

# Download the latest binary
curl -L https://ollama.com/download/ollama-linux-amd64 -o ~/ollama/bin/ollama

# Make it executable
chmod +x ~/ollama/bin/ollama

Configure Environment Variables

Open your bash configuration file to point your system to these custom directories:

nano ~/.bashrc

Scroll to the bottom of the file and paste the following lines:

export PATH=~/ollama/bin:$PATH
export LD_LIBRARY_PATH=~/ollama/lib:$LD_LIBRARY_PATH
export OLLAMA_MODELS=~/ollama/models

Save and exit (Ctrl+X, then Y, then Enter), then reload your terminal profile:

source ~/.bashrc

Start the Ollama Server & Pull a Model

Launch the background server process and download your first programming-focused LLM. In this case, we will use qwen3-coder:30b.

# Start the server in the background
nohup ollama serve > ~/ollama/logs/server.log 2>&1 &

# Pull and run the model
ollama run qwen3-coder:30b

Note: Pulling a 30B model will take some time depending on your internet connection. Once complete, you can test it by typing a prompt directly in your terminal, then type /exit to return to the normal bash prompt.

2. Install Open-WebUI

To enjoy a clean, ChatGPT-like browser interface at http://localhost:8080, we will install Open-WebUI using Python. Open-WebUI is a lightweight, open-source frontend that connects to your local Ollama server. It is heavily extensible and supports all the features you would expect from a modern LLM interface.

Create a Conda Environment (Optional but Recommended)

Using a virtual environment prevents package dependency conflicts with your base system.

conda create --name ollama_webui python=3.11 -y
conda activate ollama_webui
conda install pip -y

Install and Launch Open-WebUI

Install the package via pip:

python -m pip install open-webui

To quickly verify everything works, start the service manually:

open-webui serve

Open your browser and navigate to http://localhost:8080. Create your initial admin account. Since this application runs 100% locally on your machine, your credentials never leave your computer. Test the UI by selecting qwen3-coder:30b from the top dropdown menu and starting a conversation.

3. Automate Startup at Boot

To avoid manually running multiple commands every time you restart your PC, we can automate the process with a lightweight startup script and a cronjob.

Create the Startup Script

nano ~/ollama/start_ollama_webui.sh

Paste the following complete script:

#!/bin/bash

# 1. Load your profile environment variables (for Ollama paths)
source ~/.bashrc

# 2. Start the Ollama server in the background if it isn't running
if ! pkill -0 ollama; then
    nohup ollama serve > ~/ollama/logs/ollama.log 2>&1 &
    sleep 3 # Give it a moment to initialize
fi

# 3. Bind Open WebUI strictly to localhost only and run it
export HOST=127.0.0.1
export PORT=8080

# Initialize Conda for non-interactive shell execution
# (Adjust 'miniforge3', 'miniconda3', or 'anaconda3' path depending on your setup)
eval "$($HOME/miniforge3/bin/conda shell.bash hook)"

conda activate ollama_webui
nohup open-webui serve > ~/ollama/logs/ollama_webui.log 2>&1 &

echo "Ollama and Open-WebUI started successfully!"

Make the script executable:

chmod +x ~/ollama/start_ollama_webui.sh

Register the Cronjob

Open your system’s user crontab configuration:

crontab -e

Hint: If prompted to choose an editor, select nano by typing its corresponding number.

Add this single line at the very bottom of the file:

@reboot ~/ollama/start_ollama_webui.sh

Save and exit. Your system will now spin up both your backend LLM server and frontend UI silently on every boot. You can also trigger it manually anytime by executing bash ~/ollama/start_ollama_webui.sh.

4. Connect Ollama to VSCodium

Standard extensions like GitHub Copilot force you to log into external servers even when trying to hit a local endpoint. To keep things fully local, open, and private, we will use Continue, an outstanding open-source alternative.

Install the Extension

  1. Open VSCodium and navigate to the Extensions tab on the left sidebar (Ctrl+Shift+X).
  2. Search for Continue.
  3. Click Install and select Trust Authors if prompted.

Configure Continue for Advanced Coding

Click the Continue icon in your left sidebar, click the gear/config icon at the bottom of its panel to open config.yaml, and replace its contents with this production-ready setup. Adapt to the models you have downloaded and your hardware capabilities.

name: VSCodium Setup
version: 1.0.0
schema: v1

disableIndexing: false
ignoreRules:
  - "../**"               # Bars checking any directory above the current workspace
  - "**/node_modules/**"
  - "**/.git/**"
  - "**/__pycache__/**"
  - "*.env"
  - "*.vscode"

models:
  # Automatically pulls any model you download via Ollama for Chat/Edit roles
  - name: Ollama Autodetect
    provider: ollama
    model: AUTODETECT
    roles:
      - chat
      - edit
      - apply
    requestOptions:
      timeout: 300 # 5 minute default timeout

  # Fast ghost-text autocomplete (Runs while you type)
  - name: Qwen 2.5 Coder 7B (Autocomplete)
    provider: ollama
    model: qwen2.5-coder:7b
    roles:
      - autocomplete
  # Note: Use qwen2.5-coder:1.5b instead if your hardware experiences lag here.

  # Heavy-lifting configuration for deep thinking / repository restructuring
  - name: "qwen3-coder:30b (deep mode)"
    provider: "ollama"
    model: "qwen3-coder:30b"
    requestOptions:
      timeout: 1200 # 20 minute timeout for massive context processing
    extraBodyProperties:
      keep_alive: 30s # Automatically frees VRAM after 30 seconds of inactivity
      options:
        num_ctx: 32768      # 32K context window to hold ~10-15 mid-sized source files
        num_predict: 4096   # Allows massive, uninterrupted block generation
        temperature: 0.0    # Eliminates creativity for mathematically stable, predictable code
        top_p: 0.1          # Extreme token filtering
        top_k: 5            # Restricts choices to absolute best logical tokens

tabAutocompleteOptions:
  debounceDelay: 100        # Drops wait time to 100ms before triggering autocomplete (default is 250ms)
  maxPromptTokens: 2048     # Limits background code context chunking to keep execution snappy

Extra: Use Gemini 2.5 with Continue

You can also use Gemini 2.5 (Free) with Continue, which is a great option for those who want to leverage Google’s Gemini LLMs. However, this is not data-private, as everything is sent to Google’s / Gemini’s servers for processing. If you want to use Gemini, add the following configuration to the bottom of your Continue config.yaml file.

Get your Gemini API key from https://aistudio.google.com/, login with your normal Google account, copy the key, and replace paste-your-api-key in config.yaml with your actual key.

Note: There are token limits, so you migth run out of them. As of 2026-07, they renew every 24 hours. You can check your remaining tokens at https://aistudio.google.com/.

Note: Gemini is not free for commercial use. Please check the terms of service before using it in a commercial setting.

Note: Google might use your data to train Gemini. If you want to keep your code private/confidential, do not use Gemini.

Here comes the config:

models:
  - name: Autodetect
    provider: ollama
    model: AUTODETECT
    roles:
      - chat
      - edit
  - name: Gemini 2.5 Pro (Free)
    provider: gemini
    model: gemini-2.5-pro
    apiKey: paste-your-api-key
  - name: Gemini 2.5 Flash (Free)
    provider: gemini
    model: gemini-2.5-flash
    apiKey: paste-your-api-key

Optimize VSCodium’s User Settings

To ensure the inline completions and suggestions render beautifully alongside the Continue extension, update your main VSCodium configurations. Open your settings.json file (Ctrl+Shift+P -> Preferences: Open User Settings (JSON)) and make sure the following properties are defined:

{
  "editor.hover.enabled": "on",
  "editor.hover.delay": 150,
  "editor.parameterHints.enabled": true,
  "editor.suggestOnTriggerCharacters": true,
  "editor.bracketPairs.enabled": true,
  "editor.guides.bracketPairs": "active",
  "editor.suggest.preview": true,
  "editor.inlineSuggest.enabled": true,
  "editor.suggest.showDetails": true,
  "python.analysis.typeCheckingMode": "basic",
  "terminal.integrated.inheritEnv": true,
  "chat.disableAIFeatures": false,
  "editor.inlineSuggest.experimental.showOnSuggestConflict": "always",
  "terminal.integrated.profiles.linux": {
    "bash": {
      "path": "/bin/bash",
      "args": ["-l", "-i"]
    }
  },
  "terminal.integrated.defaultProfile.linux": "bash"
}

Now, you have a powerhouse configuration! You can use the standard chat tool in the side panel for codebase auditing, and enjoy lightning-fast, ultra-private local code completions natively as you write your scripts.
