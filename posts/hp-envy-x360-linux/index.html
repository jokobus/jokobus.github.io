Manjaro Linux on HP Envy x360 (13-bf0xxx): Fixing Issues that don't work out-of-the-box

A practical guide to running Manjaro Linux on the HP Envy x360 13-bf0xxx convertible: fixing touchscreen support with the linux-surface kernel, webcam, sleep/standby freeze issues, and dual-boot power settings.

The HP Envy x360 13 (13-bf0xxx series) is a sleek, capable 2-in-1 convertible with an excellent display, solid battery life, and high portability. However, if you attempt to run Linux on it out-of-the-box, you will quickly hit a few annoying roadbumps: the touchscreen does not register touches, the system locks up completely after you close the lid, and the modern webcam stack requires manual setup.

This guide is part of our Manjaro & Windows Dual-Boot series. The good news upfront: almost everything works seamlessly once you pair Manjaro with the linux-surface kernel and a couple of targeted kernel tweaks.

Here is the complete, step-by-step walkthrough to get the Envy x360 features working on an otherwise stock Manjaro installation to make it reliable as a daily OS.

0. Prerequisite: Disable Windows Fast Startup

If you are running Manjaro in a dual-boot setup with Windows, Fast Startup must be disabled. Windows Fast Startup puts the motherboard hardware into a proprietary hybrid hibernation state rather than cutting power cleanly. This leaves the Intel Integrated Sensor Hub (ISH) and touch digitizer controller in an uninitialized or locked state that Linux cannot reset upon booting.

  1. Boot into Windows.
  2. Open Control Panel $\rightarrow$ Power Options.
  3. In the left sidebar, click “Choose what the power button does”.
  4. Click the shield link: “Change settings that are currently unavailable”.
  5. Under Shutdown settings, uncheck “Turn on fast startup (recommended)”.
  6. Click Save changes and perform a complete shutdown.

1. Getting the Touchscreen to Work (linux-surface Kernel)

The HP Envy x360 13-bf0xxx uses Intel’s Integrated Sensor Solution (Intel ISH / IPTS) to handle touch digitizer input. Standard upstream Linux kernels do not ship the complete user-space processing daemon and patches required for this controller.

Fortunately, the linux-surface project provides kernel builds and the iptsd daemon that make Intel touchscreens on Envy convertibles work out of the box.

Step 1: Add the Linux-Surface Repository Keys

Open your terminal and import the signing keys for the repository:

wget -qO - https://raw.githubusercontent.com/linux-surface/linux-surface/master/pkg/keys/surface.asc | sudo pacman-key --add -
sudo pacman-key --finger 56C464BAAC421453
sudo pacman-key --lsign-key 56C464BAAC421453

Step 2: Add the Repository to Pacman

Open /etc/pacman.conf in your preferred editor:

sudo nano /etc/pacman.conf

Scroll to the bottom of the file and add:

[linux-surface]
Server = https://pkg.surfacelinux.com/arch/

Save the file (Ctrl+S, then Ctrl+X in nano).

Step 3: Install Kernel and Touchscreen Daemon

Update your package databases and install the surface kernel alongside iptsd (Intel Precise Touch & Stylus Daemon):

sudo pacman -Syu
sudo pacman -S linux-surface linux-surface-headers iptsd

Enable and start the touchscreen service:

sudo systemctl enable --now iptsd

Step 4: Update GRUB and Reboot

sudo update-grub
sudo reboot

(Note: If Manjaro returns command not found for update-grub, run sudo grub-mkconfig -o /boot/grub/grub.cfg instead).

Once rebooted into the linux-surface kernel, your touch display and active stylus should respond immediately.

2. Fixing System Freezes on Sleep / Lid Close

One of the most frustrating issues on Intel 12th/13th Gen convertibles running Linux is that the laptop locks up with a black screen when closing the lid or entering standby. You are forced to hold the power button for 10 seconds to hard reset.

This problem stems from two distinct issues: Intel Panel Self Refresh (PSR) and Modern Standby sleep states.

Fix 1: Disable Intel Panel Self Refresh (i915.enable_psr=0)

Intel’s PSR power-saving feature causes display controller deadlocks when waking from low-power states on many high-DPI laptop panels. Disabling it completely solves the display hang without noticeable battery degradation:

  1. Open the GRUB configuration:

    sudo nano /etc/default/grub

  2. Find the line starting with GRUB_CMDLINE_LINUX_DEFAULT. Inside the quotes, append a space and add i915.enable_psr=0.

    Example:

    GRUB_CMDLINE_LINUX_DEFAULT="quiet splash apparmor=1 security=apparmor udev.log_priority=3 i915.enable_psr=0"

Fix 2: Verify Modern Standby (s2idle)

Intel 12th Gen processors completely removed support for legacy ACPI S3 “Deep” sleep. If your Linux distribution attempts to force Deep sleep instead of s2idle (Modern Standby), the system cannot resume and locks up.

Check your current sleep state:

cat /sys/power/mem_sleep
  • [s2idle] deep: Your system is already correctly set to Modern Standby (the brackets indicate the active mode).
  • s2idle [deep]: Deep sleep is selected, which triggers lid-close freezes.

If deep is selected, append mem_sleep_default=s2idle to your GRUB line as well:

GRUB_CMDLINE_LINUX_DEFAULT="quiet splash i915.enable_psr=0 mem_sleep_default=s2idle"

Save the file and regenerate your bootloader configuration:

sudo update-grub
# Fallback if needed:
# sudo grub-mkconfig -o /boot/grub/grub.cfg

Reboot your laptop. Suspend and resume will now work reliably when opening and closing the lid.

3. Getting the Webcam Working (PipeWire & Libcamera)

Modern laptops frequently route their front-facing camera through the MIPI / IPU6 subsystem rather than a legacy USB UVC interface. To verify your hardware:

lspci | grep -i multimedia

To pipe the camera feed into your desktop applications (browsers, Zoom, Teams, Kamoso), install the libcamera stack and the PipeWire integration plugin:

sudo pacman -S libcamera libcamera-ipa libcamera-tools gst-plugin-libcamera pipewire-libcamera

Restart the user-space multimedia services:

systemctl --user restart pipewire wireplumber

Open a camera testing app (such as kamoso, snapshot, or cheese) or test your camera in Chromium / Firefox; the video stream should now initialize smoothly.

4. Current Limitation: IR Face Recognition (Howdy)

Many users look forward to using Windows Hello-style face unlock on Linux using Howdy.

⚠️
Status: IR Sensor Driver Missing
On the HP Envy x360 13-bf0xxx series, the dedicated infrared (IR) camera emitter and sensor are not yet exposed by the Linux kernel driver. While the standard RGB camera works via libcamera, the IR stream is currently unavailable. Face recognition unlock via Howdy cannot be used until upstream kernel driver patches land for this specific sensor module.

Conclusion

With the linux-surface kernel and these simple tweaks, the HP Envy x360 turns into an agile, highly responsive Linux 2-in-1 machine with excellent touch responsiveness, solid thermals, and dependable suspend/resume.
