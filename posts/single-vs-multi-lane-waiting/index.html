    Introduction

    Whenever you step into a bank or a grocery store, you encounter one of two queueing designs:

    1. Multi-Line Queuing ($c \times M/M/1$): Each register or counter has its own dedicated line. Customers pick a line and wait.
    2. Single-Line Queuing ($M/M/c$): A single “serpentine” line feeds into all available counters. The person at the front goes to the next open station.

    While multi-line setups might feel faster because individual lines look shorter, single-line systems are mathematically superior in both average wait time and queue stability. Using Markov Chain theory and Queueing Theory, we can prove why pooling capacity eliminates systemic inefficiencies.

    System Setup & Assumptions

    Consider a facility with $c$ identical servers (e.g., checkout counters), each serving customers at an average rate of $\mu$ (customers per unit time).

    Customers arrive at an overall average rate of $\lambda$. We assume standard Markovian properties (Kendall’s Notation $M/M/\dots$):

    • Arrival Process ($M$): Memoryless Poisson process with inter-arrival rate $\lambda$.
    • Service Time ($M$): Memoryless exponential distribution with mean service time $\frac{1}{\mu}$.

    To compare both configurations fairly, we set the total traffic intensity (utilization) as:

    $$\rho = \frac{\lambda}{c\mu}$$

    For the queue to remain stable and not grow infinitely, we require $\rho < 1$.

    1. Multi-Line Queuing: $c$ Independent $M/M/1$ Queues

    In a multi-line setup, incoming customers split evenly across the $c$ queues (either randomly or by choosing the shortest line upon entry). Assuming an even distribution without queue-jumping (jockeying), each queue behaves as an independent $M/M/1$ model:

    • Arrival rate per line: $\lambda_{\text{line}} = \frac{\lambda}{c}$
    • Service rate per server: $\mu$
    • Traffic intensity per line: $\rho = \frac{\lambda/c}{\mu} = \frac{\lambda}{c\mu}$

    Markov Chain State Space for $M/M/1$

    For a single $M/M/1$ queue, let $N(t)$ be the number of customers in that specific line at time $t$. The system transitions according to a continuous-time birth-death process:

     ( 0 )  <--λ/c--  ( 1 )  <--λ/c--  ( 2 )  <--λ/c--  ( 3 ) ...
        -- μ -->         -- μ -->         -- μ -->

    The expected waiting time in queue $W_q$ for an $M/M/1$ line is given by:

    $$W_q^{(M/M/1)} = \frac{\rho}{\mu(1 - \rho)} = \frac{\lambda}{c\mu^2 - \mu\lambda}$$

    2. Single-Line Queuing: The $M/M/c$ System

    In a single-line system, all arrivals join a central queue served by $c$ channels.

    Markov Chain State Space for $M/M/c$

    Let $N(t)$ be the total number of customers in the entire system (queue + servers). The state transition rates change depending on how many servers are currently active:

     ( 0 )  <--λ--  ( 1 )  <--λ--  ( 2 ) ... <--λ-- ( c )  <--λ--  ( c+1 ) ...
        --μ-->         --2μ->                  --cμ->          -- cμ ->
    • When $n < c$ customers are present, $n$ servers are working, yielding a total service rate of $n\mu$.
    • When $n \ge c$ customers are present, all $c$ servers are busy, yielding a maximum system service rate of $c\mu$.

    Using the steady-state probability of zero customers $P_0$:

    $$P_0 = \left[ \sum_{k=0}^{c-1} \frac{(c\rho)^k}{k!} + \frac{(c\rho)^c}{c!(1-\rho)} \right]^{-1}$$

    The probability that an arriving customer must wait in line is given by the Erlang-C formula:

    $$P_W = C(c, \lambda/\mu) = \frac{\frac{(c\rho)^c}{c!(1-\rho)}}{\sum_{k=0}^{c-1} \frac{(c\rho)^k}{k!} + \frac{(c\rho)^c}{c!(1-\rho)}}$$

    The expected waiting time in queue for $M/M/c$ is:

    $$W_q^{(M/M/c)} = \frac{P_W}{c\mu - \lambda}$$

    Mathematical Proof of Efficiency: The “Idle Server Waste”

    Why is $W_q^{(M/M/c)}$ strictly less than $W_q^{(M/M/1)}$? The core difference lies in the state space structure.

    In a multi-line system with $c$ separate queues, the system state is represented by a vector $(n_1, n_2, \dots, n_c)$, where $n_i$ is the number of customers in line $i$. Because lines are independent, there exists a non-zero probability of reaching a state where:

    $$n_1 > 1 \quad \text{and} \quad n_2 = 0$$

    In this state, Server 2 sits completely idle while a customer waits in Line 1. The total processing capacity of the system drops to $(c-1)\mu$, artificially inflating the average wait time across all customers.

    In contrast, an $M/M/c$ single-line system guarantees that no server sits idle as long as there is at least one customer waiting in the queue. Service capacity is dynamically pooled, enforcing maximum processing power ($c\mu$) whenever $N \ge c$.

    Numerical Example

    Consider a system with $c = 2$ servers, each serving $\mu = 1$ customer per minute, and an overall arrival rate of $\lambda = 1.6$ customers per minute ($\rho = 0.8$).

    Multi-Line System ($2 \times M/M/1$)

    • Arrival rate per line: $\lambda_{\text{line}} = 0.8$
    • Expected wait time in queue:
    $$W_q^{(M/M/1)} = \frac{0.8}{1(1 - 0.8)} = \mathbf{4.0 \text{ minutes}}$$

    Single-Line System ($M/M/2$)

    • System arrival rate: $\lambda = 1.6$
    • First, compute $P_0$:
    $$P_0 = \left[ 1 + 1.6 + \frac{1.6^2}{2!(1 - 0.8)} \right]^{-1} = \left[ 1 + 1.6 + 6.4 \right]^{-1} = \frac{1}{9} \approx 0.111$$
    • Next, evaluate Erlang-C ($P_W$):
    $$P_W = \frac{6.4}{9} \approx 0.711$$
    • Expected wait time in queue:
    $$W_q^{(M/M/2)} = \frac{0.711}{2(1) - 1.6} = \frac{0.711}{0.4} = \mathbf{1.78 \text{ minutes}}$$

    Result: By merging two independent queues into a single line, the average waiting time drops from 4.0 minutes to 1.78 minutes—a 55.5% reduction in delay with no extra staffing costs.

    Summary Comparison

    PropertyMulti-Line ($c \times M/M/1$)Single-Line ($M/M/c$)
    Idle Capacity WasteHigh (Servers idle while other lines wait)Zero (Servers process whenever queue $> 0$)
    Wait Time VarianceHigh (Stuck behind slow transactions)Low (A single long task only delays 1 server)
    Queue PolicyFirst-Come, First-Served per lineStrict First-Come, First-Served overall
    Psychological FairnessLow (Perceived unfairness if adjacent lines move faster)High (Guaranteed equity)

    Single-line queuing leverages capacity pooling to prevent server idleness, lower expected wait times, and dramatically compress queue variance.

    Example Implementation in Python

    import heapq
import math
import random


def simulate_queues(
    total_lambda: float,
    mu: float,
    c: int,
    n_customers: int = 200_000,
    seed: int = 42,
):
    random.seed(seed)

    # -------------------------------------------------------------
    # 1. Pre-generate inter-arrival times and service times
    # -------------------------------------------------------------
    # Cumulative arrival times A_i
    arrivals = []
    t = 0.0
    for _ in range(n_customers):
        t += random.expovariate(total_lambda)
        arrivals.append(t)

    service_times = [random.expovariate(mu) for _ in range(n_customers)]

    # -------------------------------------------------------------
    # 2. Single-Line Queue (M/M/c) using a Min-Heap
    # -------------------------------------------------------------
    # Min-heap stores the exact timestamp when each server becomes free
    servers_free_at = [0.0] * c
    heapq.heapify(servers_free_at)

    mmc_waits = []
    for arr_time, serv_time in zip(arrivals, service_times):
        # The next available server is the one that finishes earliest
        earliest_free = heapq.heappop(servers_free_at)

        # Start time is either when customer arrived or when server became free
        start_time = max(arr_time, earliest_free)
        mmc_waits.append(start_time - arr_time)

        # Push updated free time back into the heap
        heapq.heappush(servers_free_at, start_time + serv_time)

    # -------------------------------------------------------------
    # 3. Multi-Line Queues (c x M/M/1)
    # -------------------------------------------------------------
    # Each server has its own dedicated line free time
    line_free_at = [0.0] * c
    mm1_waits = []

    for arr_time, serv_time in zip(arrivals, service_times):
        # Customer picks a random line upon arrival
        chosen_line = random.randint(0, c - 1)

        start_time = max(arr_time, line_free_at[chosen_line])
        mm1_waits.append(start_time - arr_time)

        line_free_at[chosen_line] = start_time + serv_time

    # -------------------------------------------------------------
    # 4. Results & Comparison
    # -------------------------------------------------------------
    avg_mmc = sum(mmc_waits) / n_customers
    avg_mm1 = sum(mm1_waits) / n_customers

    print(f"--- Simulation Results ({c} Servers) ---")
    print(f"Single-Line (M/M/{c}) Wait : {avg_mmc:.4f} min")
    print(f"Multi-Line  ({c}xM/M/1) Wait: {avg_mm1:.4f} min")
    print(f"Wait Time Reduction        : {(1 - avg_mmc / avg_mm1) * 100:.2f}%")


if __name__ == "__main__":
    simulate_queues(total_lambda=1.6, mu=1.0, c=2)
