Introduction

Morse code, developed by Samuel Morse [morse1840] and standardized globally by the International Telecommunication Union [itu2009morse] , represents one of humanity’s earliest digital signaling protocols. By encoding textual information into sequences of short pulses (dots) and long pulses (dashes), it transformed global telecommunications over electrical telegraphs.

While standard hobbyist implementations typically rely on crude, blocking delay() loops that freeze the microcontroller, this project approaches visual Morse transmission with real-world embedded systems engineering principles:

  • 100% Interrupt-Driven: Utilizing hardware Timer1 in CTC mode (Clear Timer on Compare Match), leaving the Arduino loop() function completely empty.
  • Lighthouse Wave Effect: Instead of harsh, binary blinking, light sweeps across an addressable WS2812B LED strip in a fluid wave resembling a rotating coastal beacon.
  • Non-Volatile Single-Button UI: Repurposing the onboard Arduino Nano Reset button as a toggle switch by persisting state flags in the internal EEPROM.
  • Memory Optimization: Storing symbol lookup tables and messages in flash memory (PROGMEM) to preserve the ATmega328P’s scarce 2 KB SRAM.

Hardware Architecture & Wiring

The project is built on the Arduino Nano (ATmega328P) mounted onto a breakout expansion board. The ATmega328P operates at 5V logic with a 16 MHz crystal clock, perfectly matching the timing requirements of WS2812B addressable LEDs without requiring logic-level shifters.

Brightness Safety: WS2812B LEDs at 100% white can draw nearly 500 mA for 8 LEDs and cause severe eye glare when viewed directly on a workbench. The code caps brightness to 1% (BRIGHTNESS = 1), which provides crisp visual visibility while drawing minimal current from the USB rail.

Morse Timing Standards & Timer Calculations

Morse code timing is defined around the fundamental unit of time: the Dot duration ($t_{\text{dot}}$). Standard international Morse ratios dictate:

ElementStandard RatioImplemented DurationDescription
Dot (.)$1 \times t_{\text{dot}}$500 msShort signal pulse
Dash (-)$3 \times t_{\text{dot}}$1500 msLong signal pulse
Intra-character gap$1 \times t_{\text{dot}}$500 msPause between dots and dashes in the same letter
Inter-character gap$3 \times t_{\text{dot}}$1500 msPause between letters in a word
Word gap$7 \times t_{\text{dot}}$3500 msPause between distinct words

Note: While acoustic telegraphy typically uses dots around 100–200 ms, a 500 ms base dot was chosen to allow human observers to comfortably appreciate the visual wave effect.

Hardware Timer1 Configuration

To keep the main loop() completely empty and avoid CPU starvation, all timing is offloaded to the 16-bit Timer1:

  1. Clock Frequency: $f_{\text{cpu}} = 16\,\text{MHz}$
  2. Prescaler: 1024 (via register bits CS12 and CS10)
  3. Timer Clock: $$f_{\text{timer}} = \frac{16\,\text{MHz}}{1024} = 15{,}625\,\text{Hz}$$
  4. Tick Duration: $$\Delta t_{\text{tick}} = \frac{1}{15{,}625\,\text{Hz}} = 64\,\mu\text{s}$$
  5. Maximum Achievable Interval: $$T_{\text{max}} = 65{,}536 \times 64\,\mu\text{s} \approx 4.194\,\text{seconds}$$

Because our longest interval (the 3500 ms word gap) is well under 4.194 seconds, Timer1 can handle all Morse timing intervals natively without secondary software counters.

The compare match value loaded into register OCR1A is calculated on each step transition via:

$$\text{OCR1A} = \left(\frac{\text{Duration}_{\text{ms}} \times 15625}{1000}\right) - 1$$

Timing Precision & Error Analysis

With a $64\,\mu\text{s}$ time base, the relative quantization error for our 500 ms dot interval is virtually non-existent:

$$\text{Relative Error} = \frac{64\,\mu\text{s}}{500\,\text{ms}} = 0.0128\%$$

Software Architecture & Key Mechanisms

1. The Sweeping Lighthouse Wave Effect

Instead of blinking all 8 LEDs simultaneously, the transmission duration is divided into sub-intervals across the strip:

$$\text{Duration per LED} = \frac{\text{Symbol Duration}}{\text{LED Count}} = \frac{500\,\text{ms}}{8} = 62.5\,\text{ms}$$

As the Timer1 interrupt fires, the active center moves sequentially from LED 0 to LED 7. The parameter WAVE_WIDTH = 5 illuminates the center LED and its immediate neighbors to create a smooth, moving optical beam with soft edges:

LED 0   [ █ ] [ █ ] [ ░ ] [   ] [   ] [   ] [   ] [   ]   (Beginning of pulse)
LED 3   [   ] [ ░ ] [ █ ] [ █ ] [ █ ] [ ░ ] [   ] [   ]   (Mid-pulse sweep)
LED 7   [   ] [   ] [   ] [   ] [   ] [ ░ ] [ █ ] [ █ ]   (End of pulse)

Boundary checking prevents index wrapping across the edges of the strip. Setting WAVE_WIDTH = 0 reverts the transmitter to standard synchronous blinking.

2. Single-Button UI via Non-Volatile EEPROM

Because the Arduino Nano board contains only a single physical pushbutton (the hardware Reset button), we store the current running state in EEPROM byte 0:

stateDiagram-v2

Wear-Leveling Safeguard

The ATmega328P EEPROM is rated for approximately 100,000 write cycles. Writing blindly on every boot could prematurely wear out the cell. By checking if (EEPROM.read(0) != state) prior to EEPROM.write(0, state), unnecessary write cycles are eliminated.

Complete Arduino Source Code (morse.ino)

Below is the complete, heavily documented source code as found in the repository:

// Arduino: Nano Atmel mega328p
// LED: WS2812B (CJMCU-2812-8)
// Used: Timer1 CTC, prescaler 1024, Button interupt

#include <Arduino.h>
#include <Adafruit_NeoPixel.h>    // LED control
#include <EEPROM.h>               // State persistence across resets

// Target message to transmit
const char MESSAGE[] = "IN";      ///< Change this to any desired text

// Hardware configuration
const uint8_t LED_PIN = 6;        ///< Digital output pin for WS2812B data
const uint8_t WAVE_WIDTH = 5;     ///< 0 = normal blinking, >0 = lighthouse sweeping effect
const uint8_t LED_COUNT = 8;      ///< Total LEDs on the strip

// Morse Code Timing Standards (in milliseconds)
const uint16_t TIME_DOT = 500;          ///< Base dot duration
const uint16_t TIME_DASH = 1500;        ///< Dash duration (3x dot)
const uint16_t TIME_SYMBOL_GAP = 500;   ///< Gap between dots/dashes
const uint16_t TIME_LETTER_GAP = 1500;  ///< Gap between characters
const uint16_t TIME_WORD_GAP = 3500;    ///< Gap between words
const uint8_t BRIGHTNESS = 1;           ///< Dim 1% brightness to protect eyes

// NeoPixel strip object instantiation
Adafruit_NeoPixel led_strip(LED_COUNT, LED_PIN, NEO_GRB + NEO_KHZ800);

// Hardware Timer1 calibration (16MHz / 1024 = 15625 Hz)
const uint16_t TICKS_PER_SECOND = 15625;
const uint8_t MAX_STEPS = 100;

// Dynamic animation step arrays
uint16_t durations[MAX_STEPS];            ///< Step duration in ms
uint32_t colors[MAX_STEPS];               ///< Step RGB color
uint8_t ledIndex[MAX_STEPS];              ///< Target center LED (255 = all)
uint8_t stepCount = 0;
volatile uint8_t currentStep = 0;

/**
 * @brief Flash-based lookup table converting ASCII characters to Morse dots & dashes.
 */
const char* morseCode(char c) {
  switch (c) {
    case 'A': return ".-";   case 'B': return "-..."; case 'C': return "-.-.";
    case 'D': return "-..";  case 'E': return ".";    case 'F': return "..-.";
    case 'G': return "--.";  case 'H': return "...."; case 'I': return "..";
    case 'J': return ".---"; case 'K': return "-.-";  case 'L': return ".-..";
    case 'M': return "--";   case 'N': return "-.";   case 'O': return "---";
    case 'P': return ".--."; case 'Q': return "--.-"; case 'R': return ".-.";
    case 'S': return "...";  case 'T': return "-";    case 'U': return "..-";
    case 'V': return "...-"; case 'W': return ".--";  case 'X': return "-..-";
    case 'Y': return "-.--"; case 'Z': return "--..";
    case '0': return "-----"; case '1': return ".----"; case '2': return "..---";
    case '3': return "...--"; case '4': return "....-"; case '5': return ".....";
    case '6': return "-...."; case '7': return "--..."; case '8': return "---..";
    case '9': return "----.";
    default:  return "";
  }
}

/**
 * @brief Records a discrete animation step into the sequence buffer.
 */
void addStep(uint16_t duration_ms, uint32_t color, uint8_t ledIdx = 255) {
  if (stepCount < MAX_STEPS) {
    durations[stepCount] = duration_ms;
    colors[stepCount] = color;
    ledIndex[stepCount] = ledIdx;
    stepCount++;
  }
}

/**
 * @brief Compiles the ASCII message into a sequence of LED animation steps.
 */
void buildSequence() {
  stepCount = 0;
  const uint32_t WHITE = led_strip.Color(255, 255, 255);
  const uint32_t OFF = 0;
  
  for (const char* p = MESSAGE; *p; ++p) {
    char c = toupper(*p);
    if (c == ' ') {
      addStep(TIME_WORD_GAP, OFF);
      continue;
    }
    const char* code = morseCode(c);
    if (!*code) continue;

    for (const char* s = code; *s; ++s) {
      uint16_t onDur = (*s == '.') ? TIME_DOT : TIME_DASH;
      uint16_t perLedDur = onDur / LED_COUNT;
      
      // Sweep light sequentially across the strip
      for (uint8_t i = 0; i < LED_COUNT; i++) {
        addStep(perLedDur, WHITE, i);
      }
      
      if (*(s + 1)) {
        addStep(TIME_SYMBOL_GAP, OFF);
      }
    }
    addStep(TIME_LETTER_GAP, OFF);
  }
  addStep(TIME_WORD_GAP, OFF);
  
  // Visual return wave before looping
  for (uint8_t i = LED_COUNT; i > 0; i--) {
    addStep(20, WHITE, i);
  }
  addStep(TIME_WORD_GAP, OFF);
}

/**
 * @brief Timer1 Compare Match A Interrupt Service Routine.
 * Executes on each step transition, updates the LEDs, and dynamically reloads OCR1A.
 */
ISR(TIMER1_COMPA_vect) {
  if (ledIndex[currentStep] == 255 || WAVE_WIDTH == 0) {
    led_strip.fill(colors[currentStep]);
  } else {
    led_strip.clear();
    if (colors[currentStep] != 0) {
      int8_t center = ledIndex[currentStep];
      int8_t halfWidth = WAVE_WIDTH / 2;
      
      for (int8_t offset = -halfWidth; offset <= halfWidth; offset++) {
        int8_t ledPos = center + offset;
        if (ledPos >= 0 && ledPos < LED_COUNT) {
          led_strip.setPixelColor(ledPos, colors[currentStep]);
        }
      }
    }
  }
  led_strip.show();
  
  // Reload compare register for the next step's duration
  uint32_t ticks = ((uint32_t)durations[currentStep] * TICKS_PER_SECOND) / 1000UL;
  if (ticks < 100) ticks = 100;
  OCR1A = (uint16_t)(ticks - 1);
  
  currentStep++;
  if (currentStep >= stepCount) {
    currentStep = 0;
  }
}

void showStartupSequence() {
  led_strip.fill(led_strip.Color(255, 0, 0)); led_strip.show(); delay(500);
  led_strip.fill(led_strip.Color(0, 255, 0)); led_strip.show(); delay(500);
  led_strip.fill(0); led_strip.show(); delay(500);
}

void showShutdownSequence() {
  led_strip.fill(led_strip.Color(0, 255, 0)); led_strip.show(); delay(500);
  led_strip.fill(led_strip.Color(255, 0, 0)); led_strip.show(); delay(500);
  led_strip.fill(0); led_strip.show(); delay(500);
}

void setup() {
  led_strip.begin();
  led_strip.setBrightness((255 * BRIGHTNESS) / 100);

  // Read and toggle non-volatile running state from EEPROM
  byte state = EEPROM.read(0);
  state = !state;
  if (EEPROM.read(0) != state) {
    EEPROM.write(0, state);
  }
  
  if (state) {
    showStartupSequence();
    currentStep = 0;
    buildSequence();

    // Configure Timer1 for CTC mode with 1024 prescaler
    cli();
    TCCR1A = 0;
    TCCR1B = 0;
    TCCR1B |= (1 << WGM12);              // CTC mode
    TCCR1B |= (1 << CS12) | (1 << CS10); // Prescaler 1024
    OCR1A = 1562;                        // Initial ~100ms trigger
    TIMSK1 |= (1 << OCIE1A);             // Enable Timer1 Compare Match A interrupt
    sei();
  } else {
    showShutdownSequence();
    TIMSK1 &= ~(1 << OCIE1A);            // Disable interrupt
    TCCR1B = 0;                          // Stop clock
  }
}

void loop() {
  // Main loop remains 100% free for async processing or power savings
}

Key Engineering Takeaways

  1. Deterministic Execution: Because the timing is generated directly by hardware counters, software interrupts ensure that the pulse intervals never stutter or drift, even if background communications are added later.
  2. ISR Execution Overhead vs. WS2812B Bit-Banging: The WS2812B protocol is timing-sensitive and requires $24\,\text{bits} \times 8\,\text{LEDs} \times 1.25\,\mu\text{s} \approx 240\,\mu\text{s}$ of bit-banging inside led_strip.show(). While executing long blocking tasks inside an ISR is generally discouraged, $240\,\mu\text{s}$ represents less than 0.05% of our shortest 500 ms Morse interval, producing zero measurable timing jitter.
  3. RAM Preservation: With only 2048 bytes of SRAM available on the ATmega328P, keeping the sequence buffer at 100 steps consumes roughly 700 bytes, leaving over 1.3 KB of memory free.
