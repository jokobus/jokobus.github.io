Deploy Hugo on your Homeserver via GitHub Actions

A complete, secure workflow for deploying a Hugo website on your own Linux homeserver via GitHub Actions. Your markdown source files and compiled code remain private, deployment is fully automated, and your server stays safely protected behind its firewall with port 22 closed.

Security Highlights of this Architecture

  • Port 22 (SSH) Remains Completely Closed: The home server pulls updates outbound over HTTPS or SSH Deploy Keys. No open inbound ports for SSH brute-force attackers.
  • Source Files Remain Private: Your Markdown drafts, unreleased posts, and configuration stay in your private GitHub repository (hugo-source).
  • Continuous Integration: GitHub Actions compiles the site with Hugo Extended and the Smidr theme submodule, then pushes only the static HTML/CSS to your deployment target.
  • Native SSL & Compression: Caddy handles automatic Let’s Encrypt certificates, HTTP/3, and Zstandard/Gzip compression out of the box.

Architectural Overview

[Local Workstation]
        │
        ▼ (git push: Markdown + Smidr Submodule)
[GitHub: hugo-source] (Private)
        │
        ▼ (GitHub Actions: Hugo Extended Build)
[GitHub: hugo-public] (Private Deploy Repo)
        ▲
        │ (Every 5 min: Outbound 'git pull' via SSH Deploy Key)
[Home Server / Raspberry Pi]
        ├── /var/www/hugo-public (Static Assets)
        └── Caddy Reverse Proxy (Ports 80/443 for Public Web Only)
  1. hugo-source (Private Repo): Houses your Markdown content, theme submodule (themes/smidr), and hugo.yaml.
  2. hugo-public (Private Repo): Stores only the compiled static HTML, CSS, JavaScript, and images generated by Hugo.
  3. GitHub Actions: Whenever you push to hugo-source, the runner checks out submodules, builds the static site with hugo --minify, and pushes the result to hugo-public.
  4. Home Server: Runs a quiet cron job every 5 minutes that executes git pull using a read-only SSH Deploy Key. If changes are detected, Caddy serves them immediately.

Prerequisites

Before starting, ensure you have:

  1. A GitHub account.
  2. A private Hugo repository (hugo-source) set up with the Smidr theme (see Part 1).
  3. A Linux machine (Raspberry Pi, mini PC, or VPS) with Caddy installed.
  4. A domain name (or dynamic DNS like DuckDNS) pointing to your public home IP address.
  5. Inbound router ports 80 and 443 forwarded to your server for web traffic. (Port 22 for SSH should remain closed).

Step 1: Create the Deployment Repository and Token

Because GitHub Actions runners operate within an isolated environment, we must grant the action on hugo-source permission to push compiled code into hugo-public.

1.1 Create the Target Repository

  1. Log into GitHub and create a new repository called hugo-public.
  2. Set the repository visibility to Private (or Public if you want anyone to inspect the compiled HTML).
  3. Initialize it with a README.md so that the default main branch is created.

1.2 Generate a Fine-Grained Personal Access Token

  1. In your GitHub profile, navigate to Settings → Developer Settings → Personal Access Tokens → Fine-grained tokens.
  2. Click Generate new token and name it hugo-compiler-token.
  3. Under Repository access, select Only select repositories and pick your hugo-public repo.
  4. Under Permissions, expand Repository permissions, find Contents, and set it to Read and Write.
  5. Click Generate token and copy the generated secret key.

1.3 Add the Secret to Your Source Repository

  1. Navigate to your hugo-source repository on GitHub.
  2. Go to Settings → Secrets and variables → Actions → New repository secret.
  3. Set the name to PUBLIC_REPO_TOKEN and paste the token from the previous step.

Step 2: Configure the GitHub Actions Workflow

In your local hugo-source repository, create .github/workflows/compile.yml:

name: Compile Hugo and Deploy to Public Repo

on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      # Step 1: Checkout source code and submodules (crucial for Smidr theme)
      - name: Checkout Source & Themes
        uses: actions/checkout@v4
        with:
          submodules: true
          fetch-depth: 0

      # Step 2: Install Hugo Extended
      - name: Setup Hugo Extended
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: 'latest'
          extended: true

      # Step 3: Compile minified static files
      - name: Build Static Site
        # Note: If your site uses environment-specific config, use: hugo --minify --environment rpi
        run: hugo --minify

      # Step 4: Push compiled HTML to the target deployment repository
      - name: Push to Target Repo
        uses: cpina/github-action-push-to-another-repository@main
        env:
          API_TOKEN_GITHUB: ${{ secrets.PUBLIC_REPO_TOKEN }}
        with:
          source-directory: 'public'
          destination-github-username: 'YOUR_GITHUB_USERNAME'
          destination-repository-name: 'hugo-public'
          user-email: 'your-email@example.com'
          target-branch: 'main'
💡
Hugo Environments

If you run different configurations for local development, GitHub Pages, and your homeserver (e.g. config/_default/ and config/rpi/), you can target specific environments directly in the build step:

run: hugo --minify --environment rpi

This allows you to change the baseURL, analytics, or parameters without modifying your core source files.

Commit and push this file to your hugo-source repository:

git add .github/workflows/compile.yml
git commit -m "Add automated Hugo compilation workflow"
git push origin main

Under the Actions tab on GitHub, you should see the pipeline run and complete in under 60 seconds.

Step 3: Set Up a Read-Only SSH Deploy Key on Your Server

Your server needs read-only access to pull down updates from hugo-public without storing your personal GitHub account password or full write tokens.

Log into your home server terminal via local network and follow these steps:

3.1 Generate an Ed25519 Keypair

ssh-keygen -t ed25519 -f ~/.ssh/id_github_blog -C "homeserver-blog-puller"

Press Enter twice to leave the passphrase empty so automated scripts can authenticate without human interaction.

3.2 Add the Public Key to GitHub

Display the public key and copy it:

cat ~/.ssh/id_github_blog.pub
  1. Go to your hugo-public repository on GitHub.
  2. Navigate to Settings → Deploy Keys → Add deploy key.
  3. Title it homeserver-caddy-puller, paste the key, and leave “Allow write access” unchecked.

3.3 Configure SSH Client on Your Server

Edit ~/.ssh/config (create it if it doesn’t exist):

nano ~/.ssh/config

Add the following block:

Host github-blog
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_github_blog
    IdentitiesOnly yes

Ensure secure permissions:

chmod 600 ~/.ssh/config ~/.ssh/id_github_blog
chmod 644 ~/.ssh/id_github_blog.pub

3.4 Clone the Repository to the Web Root

Create the directory where Caddy will serve the site:

sudo mkdir -p /var/www/hugo-public
sudo chown -R $USER:$USER /var/www/hugo-public

Clone the repository using the SSH alias:

git clone git@github-blog:YOUR_GITHUB_USERNAME/hugo-public.git /var/www/hugo-public

Verify that the compiled HTML files are present:

ls -la /var/www/hugo-public

Step 4: Automate Pulls with a Silent Cron Job

Because the server initiates the pull outward to GitHub, no inbound firewall ports (like port 22) need to be open.

Open your user’s crontab editor:

crontab -e

Add the following line at the bottom:

*/5 * * * * cd /var/www/hugo-public && git pull origin main >/dev/null 2>&1
  • */5 * * * *: Checks for updates every 5 minutes.
  • cd /var/www/hugo-public && git pull: Fetches any new commits from GitHub. If there are no new commits, Git exits immediately with minimal resource usage.
  • >/dev/null 2>&1: Suppresses terminal output and emails when there are no errors.

Save and exit. Your server will now automatically stay in sync with your GitHub deployment repository.

Step 5: Configure the Caddy Web Server

Caddy is an ultra-fast, modern web server that provisions and renews SSL certificates from Let’s Encrypt completely automatically.

💡
Pair with our Homeserver Architecture
This Caddy configuration matches the reverse proxy design detailed in our Raspberry Pi 4 Homeserver Guide: Nextcloud, Immich & Caddy. If you already run Caddy on your homeserver as described in that guide, serving your static Hugo blog is as simple as adding the server block below to your main Caddyfile!

Open your Caddyfile:

sudo nano /etc/caddy/Caddyfile

Add your site configuration block:

your-domain.com {
    # Path to compiled static files
    root * /var/www/hugo-public

    # Serve static files directly
    file_server

    # Modern compression for blazing speed
    encode zstd gzip

    # Custom 404 page handling
    handle_errors {
        rewrite * /{err.status_code}.html
        file_server
    }
}
💡
Permissions

Ensure Caddy’s process can read the files:

sudo chmod -R 755 /var/www/hugo-public

Reload Caddy

Apply the changes to Caddy:

  • If running as a systemd service:
    sudo systemctl reload caddy
  • If running via Docker Compose:
    docker compose exec caddy caddy reload

Testing the Complete Pipeline

Your end-to-end publishing pipeline is now operational:

  1. Edit locally: Write or revise an article in your local website folder.
  2. Commit & Push:
    git add -A
git commit -m "Publish new post on robotics"
git push origin main
  3. Automated Build: GitHub Actions detects the push, builds the site using Hugo Extended and the Smidr theme, and updates hugo-public.
  4. Automated Server Pull: Within 5 minutes, your server pulls down the new files via cron.
  5. Instant Delivery: Visit your domain in any browser — your new content is live, encrypted with HTTPS, and served at top speed!
