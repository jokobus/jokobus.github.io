Hugo auf dem Homeserver via GitHub Actions deployen

📅 28. Jun 2024 ⏱️ ~5 Min. Lesezeit (996 Wörter) #Hugo #GitHub Actions #Self-Hosting #Caddy #DevOps

Dies ist Teil 2 unserer Hugo-Serie. In Teil 1: Blog mit Hugo und Smidr erstellen haben wir gezeigt, wie man einen modernen Blog lokal mit Hugo Extended und dem Smidr-Theme aufbaut.

In diesem Teil bringen wir das Setup in die Produktion auf eigener Hardware. Diese Anleitung zeigt, wie eine Hugo-Website vollautomatisiert auf einen Linux-Homeserver (wie z. B. einen Raspberry Pi) oder VPS hinter einem Caddy-Webserver deployt wird.

Sicherheitsvorteile dieser Architektur

  • Port 22 (SSH) bleibt vollständig geschlossen: Der Homeserver zieht Aktualisierungen aktiv nach außen über HTTPS bzw. SSH-Deploy-Keys. Es gibt keine offenen SSH-Ports im Internet für Brute-Force-Angriffe.
  • Quelldateien bleiben privat: Entwürfe, unfertige Artikel und Konfigurationsdateien verbleiben sicher im privaten GitHub-Quell-Repository (hugo-source).
  • Continuous Integration: GitHub Actions baut die Website mit Hugo Extended und dem Smidr-Theme-Submodul und pusht ausschließlich das kompilierte statische HTML/CSS auf das Deployment-Ziel.
  • Automatische SSL-Zertifikate & Kompression: Caddy kümmert sich vollautomatisch um Let’s Encrypt-Zertifikate, HTTP/3 sowie Zstandard/Gzip-Kompression.

Architektur-Übersicht

[Lokaler Arbeitsplatz]
        │
        ▼ (git push: Markdown + Smidr-Submodul)
[GitHub: hugo-source] (Privat)
        │
        ▼ (GitHub Actions: Hugo Extended Build)
[GitHub: hugo-public] (Privates Deployment-Repo)
        ▲
        │ (Alle 5 Min: Ausgehender 'git pull' via SSH-Deploy-Key)
[Homeserver / Raspberry Pi]
        ├── /var/www/hugo-public (Statische Website)
        └── Caddy Reverse Proxy (Nur Ports 80/443 für Webverkehr)
  1. hugo-source (Privates Repo): Beherbergt deine Inhalte, das Theme-Submodul (themes/smidr) und die hugo.yaml.
  2. hugo-public (Privates Repo): Speichert ausschließlich das fertig generierte statische HTML/CSS.
  3. GitHub Actions: Sobald ein Push in hugo-source erfolgt, baut GitHub Actions die Seite mit hugo --minify und überträgt das Ergebnis in hugo-public.
  4. Homeserver: Ein leichtgewichtiger Cronjob führt alle 5 Minuten ein git pull über einen schreibgeschützten SSH-Deploy-Key aus. Caddy liefert die neuen Dateien sofort aus.

Voraussetzungen

  1. Ein GitHub-Konto.
  2. Ein privates Hugo-Repository (hugo-source) mit eingerichtetem Smidr-Theme (siehe Teil 1).
  3. Ein Linux-Server (z. B. Raspberry Pi) mit installiertem Caddy.
  4. Eine eigene Domain oder Dynamic DNS (z. B. DuckDNS), die auf deine öffentliche IP verweist.
  5. Im Router freigegebene Ports 80 und 443 für Webverkehr. (Port 22 für SSH bleibt zu).

Schritt 1: Deployment-Repository und Token anlegen

1.1 Ziel-Repository erstellen

  1. Auf GitHub ein neues Repository namens hugo-public anlegen.
  2. Die Sichtbarkeit auf Private stellen (oder Public).
  3. Mit einer README.md initialisieren, damit der Standardbranch main existiert.

1.2 Fine-Grained Personal Access Token generieren

  1. In den GitHub-Profileinstellungen auf Settings → Developer Settings → Personal Access Tokens → Fine-grained tokens gehen.
  2. Auf Generate new token klicken und als Namen z. B. hugo-compiler-token wählen.
  3. Unter Repository access die Option Only select repositories wählen und das hugo-public-Repository auswählen.
  4. Unter Permissions → Repository permissions das Recht Contents auf Read and Write setzen.
  5. Den Token kopieren.

1.3 Secret im Quell-Repository hinterlegen

  1. Im Quell-Repository (hugo-source) auf GitHub zu Settings → Secrets and variables → Actions → New repository secret navigieren.
  2. Als Namen PUBLIC_REPO_TOKEN wählen und den kopierten Token einfügen.

Schritt 2: GitHub Actions Workflow einrichten

Erstelle im lokalen Quell-Repository die Datei .github/workflows/compile.yml:

name: Compile Hugo and Deploy to Public Repo

on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      # Schritt 1: Quellcode inklusive Submodulen auschecken (wichtig für Smidr)
      - name: Checkout Source & Themes
        uses: actions/checkout@v4
        with:
          submodules: true
          fetch-depth: 0

      # Schritt 2: Hugo Extended installieren
      - name: Setup Hugo Extended
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: 'latest'
          extended: true

      # Schritt 3: Statische Dateien minifiziert bauen
      - name: Build Static Site
        # Falls Umgebungen verwendet werden: hugo --minify --environment rpi
        run: hugo --minify

      # Schritt 4: Fertiges HTML ins Ziel-Repository übertragen
      - name: Push to Target Repo
        uses: cpina/github-action-push-to-another-repository@main
        env:
          API_TOKEN_GITHUB: ${{ secrets.PUBLIC_REPO_TOKEN }}
        with:
          source-directory: 'public'
          destination-github-username: 'DEIN_GITHUB_BENUTZERNAME'
          destination-repository-name: 'hugo-public'
          user-email: 'deine-email@example.com'
          target-branch: 'main'
💡
Hugo Umgebungen

Wenn du für lokale Entwicklung, GitHub Pages und Homeserver unterschiedliche Konfigurationen nutzt (z. B. config/_default/ und config/rpi/), kannst du die Umgebung direkt im Build-Schritt angeben:

run: hugo --minify --environment rpi

Dadurch können baseURL und Parameter passgenau gesteuert werden.

Committe und pushe die Datei ins Quell-Repository:

git add .github/workflows/compile.yml
git commit -m "Automatisches Deployment via GitHub Actions hinzugefügt"
git push origin main

Schritt 3: Schreibgeschützten SSH-Deploy-Key auf dem Server einrichten

Damit der Server die Änderungen von GitHub abrufen kann, ohne ein Benutzerpasswort zu benötigen, richten wir einen schreibgeschützten SSH-Schlüssel ein.

Führe folgende Befehle auf deinem Server aus:

3.1 Ed25519-Schlüsselpaar generieren

ssh-keygen -t ed25519 -f ~/.ssh/id_github_blog -C "homeserver-blog-puller"

Zweimal Enter drücken, um die Passphrase leer zu lassen.

3.2 Öffentlichen Schlüssel auf GitHub hinterlegen

Den Inhalt des öffentlichen Schlüssels anzeigen und kopieren:

cat ~/.ssh/id_github_blog.pub
  1. Im hugo-public-Repository auf GitHub zu Settings → Deploy Keys → Add deploy key navigieren.
  2. Titel vergeben (z. B. homeserver-caddy-puller), Schlüssel einfügen und “Allow write access” deaktiviert lassen.

3.3 SSH-Konfiguration anpassen

Die Datei ~/.ssh/config anlegen oder bearbeiten:

nano ~/.ssh/config

Folgenden Eintrag hinzufügen:

Host github-blog
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_github_blog
    IdentitiesOnly yes

Rechte sicherstellen:

chmod 600 ~/.ssh/config ~/.ssh/id_github_blog
chmod 644 ~/.ssh/id_github_blog.pub

3.4 Website-Verzeichnis anlegen und klonen

sudo mkdir -p /var/www/hugo-public
sudo chown -R $USER:$USER /var/www/hugo-public

Repository klonen:

git clone git@github-blog:DEIN_GITHUB_BENUTZERNAME/hugo-public.git /var/www/hugo-public

Schritt 4: Automatischer Abruf per Cronjob

Da der Server die Verbindung zu GitHub selbst aufbaut, muss kein SSH-Port nach außen geöffnet werden.

Crontab auf dem Server öffnen:

crontab -e

Folgende Zeile am Ende einfügen:

*/5 * * * * cd /var/www/hugo-public && git pull origin main >/dev/null 2>&1
  • */5 * * * *: Prüft alle 5 Minuten auf Updates.
  • cd /var/www/hugo-public && git pull: Holt neue Commits ab. Wenn nichts geändert wurde, beendet sich Git ressourcenschonend sofort.
  • >/dev/null 2>&1: Verhindert unnötige Konsolenausgaben.

Schritt 5: Caddy-Webserver konfigurieren

Caddy verwaltet SSL-Zertifikate von Let’s Encrypt vollautomatisch.

Öffne die Caddyfile:

sudo nano /etc/caddy/Caddyfile

Konfiguration eintragen:

deine-domain.de {
    # Pfad zu den kompilierten Dateien
    root * /var/www/hugo-public

    # Statische Dateien ausliefern
    file_server

    # Schnelle Kompression aktivieren
    encode zstd gzip

    # Eigene 404-Fehlerseite ausliefern
    handle_errors {
        rewrite * /{err.status_code}.html
        file_server
    }
}
💡
Dateirechte

Stelle sicher, dass Caddy Leserechte auf das Verzeichnis hat:

sudo chmod -R 755 /var/www/hugo-public

Caddy neu laden:

sudo systemctl reload caddy

Fazit & Veröffentlichung

Der automatisierte Veröffentlichungs-Workflow ist fertig eingerichtet:

  1. Beitrag lokal schreiben oder anpassen.
  2. Ins Quell-Repository pushen (git push origin main).
  3. GitHub Actions baut den Blog mit Hugo Extended und dem Smidr-Theme.
  4. Der Homeserver bezieht die Aktualisierungen innerhalb von 5 Minuten.
  5. Caddy liefert die neue Version sofort via HTTPS aus.
