Einführung

Der von Samuel Morse entwickelte [morse1840] und von der Internationalen Fernmeldeunion ITU genormte [itu2009morse] Morsecode gilt als eines der ersten digitalen Kommunikationsprotokolle der Menschheit. Durch die Kodierung von Zeichen in Folgen aus kurzen Signalen (Punkten) und langen Signalen (Strichen) revolutionierte er die weltweite Telegrafie über Kupferdrähte.

Typische Hobby-Projekte greifen bei der optischen Signalausgabe meist auf blockierende delay()-Schleifen zurück, die den Mikrocontroller komplett lahmlegen. Dieses Projekt hingegen setzt auf sauberes Embedded-Systems-Engineering:

  • 100% Interrupt-gesteuert: Der 16-Bit-Hardware-Timer Timer1 arbeitet im CTC-Modus (Clear Timer on Compare Match). Die Hauptschleife loop() bleibt vollständig leer.
  • Leuchtturm-Welleneffekt: Statt eines abrupten Blinkens wandert das Licht in einer flüssigen Wellenbewegung über einen adressierbaren WS2812B-LED-Streifen – ähnlich dem rotierenden Strahl eines Leuchtturms.
  • Nicht-flüchtige Ein-Knopf-Bedienung: Der bordeigene Reset-Taster des Arduino Nano dient als Ein-/Ausschalter, indem der aktuelle Betriebszustand im internen EEPROM gespeichert wird.
  • Speicheroptimierung: Zeichentabellen und Nachrichten werden im Flash-Speicher (PROGMEM) abgelegt, um den knappen 2-KB-SRAM des ATmega328P zu schonen.

[!TIP] Blend- und Stromschutz: WS2812B-LEDs ziehen bei 100% weißem Licht fast 500 mA für 8 LEDs und blenden bei direktem Blickkontakt extrem. Die Software drosselt die Helligkeit fest auf 1% (BRIGHTNESS = 1), was eine klare Signalanzeige gewährleistet und den USB-Anschluss minimal belastet.

Morse-Timing-Standards & Timer-Berechnung

Die zeitliche Abstimmung folgt den internationalen Morse-Konventionen, basierend auf der Punkt-Dauer ($t_{\text{dot}}$):

ElementStandardverhältnisDauer im ProjektBeschreibung
Punkt (.)$1 \times t_{\text{dot}}$500 msKurzer Signalimpuls
Strich (-)$3 \times t_{\text{dot}}$1500 msDreifache Punktdauer
Pause im Zeichen$1 \times t_{\text{dot}}$500 msAbstand zwischen Punkten/Strichen desselben Zeichens
Pause zwischen Buchstaben$3 \times t_{\text{dot}}$1500 msAbstand zwischen einzelnen Buchstaben
Pause zwischen Wörtern$7 \times t_{\text{dot}}$3500 msWortzwischenraum

Hinweis: Im Telegrafiefunk liegt die Punktdauer meist bei 100–200 ms. Für das menschliche Auge wurde eine verlängerte Basisdauer von 500 ms gewählt, um der Wellenanimation optisch folgen zu können.

Konfiguration des Hardware-Timer1

Um die Hauptschleife loop() komplett frei zu halten, übernimmt der 16-Bit-Timer Timer1 die Zeitsteuerung:

  1. Taktfrequenz: $f_{\text{cpu}} = 16\,\text{MHz}$
  2. Prescaler (Vorteiler): 1024 (Registerbits CS12 und CS10)
  3. Timer-Takt: $$f_{\text{timer}} = \frac{16\,\text{MHz}}{1024} = 15{,}625\,\text{Hz}$$
  4. Schrittdauer eines Ticks: $$\Delta t_{\text{tick}} = \frac{1}{15{,}625\,\text{Hz}} = 64\,\mu\text{s}$$
  5. Maximal messbares Intervall: $$T_{\text{max}} = 65{,}536 \times 64\,\mu\text{s} \approx 4{,}194\,\text{Sekunden}$$

Da das längste Intervall (die Wortpause mit 3500 ms) unter 4,194 Sekunden liegt, kann Timer1 jedes Zeitintervall direkt ohne Software-Überlaufzähler abbilden.

Der in das Vergleichsregister OCR1A zu ladende Wert berechnet sich bei jedem Animationsschritt dynamisch:

$$\text{OCR1A} = \left(\frac{\text{Dauer}_{\text{ms}} \times 15625}{1000}\right) - 1$$

Genauigkeits- und Fehleranalyse

Mit der Basisauflösung von $64\,\mu\text{s}$ ist der Quantisierungsfehler eines 500-ms-Impulses vernachlässigbar:

$$\text{Relativer Fehler} = \frac{64\,\mu\text{s}}{500\,\text{ms}} = 0{,}0128\%$$

Software-Architektur & Funktionsweise

1. Der Leuchtturm-Welleneffekt

Anstatt den gesamten LED-Streifen synchron an- und auszuschalten, wird die Leuchtdauer eines Symbols gleichmäßig auf die 8 LEDs aufgeteilt:

$$\text{Dauer pro LED} = \frac{\text{Symbol-Dauer}}{\text{LED-Anzahl}} = \frac{500\,\text{ms}}{8} = 62{,}5\,\text{ms}$$

Bei jedem Timer1-Interrupt rückt die aktive Mitte um eine LED-Position weiter (0 bis 7). Die Konstante WAVE_WIDTH = 5 lässt die Nachbar-LEDs mitleuchten, wodurch ein flüssiger, optisch weicher Lichtkegel entsteht:

LED 0   [ █ ] [ █ ] [ ░ ] [   ] [   ] [   ] [   ] [   ]   (Impulsbeginn)
LED 3   [   ] [ ░ ] [ █ ] [ █ ] [ █ ] [ ░ ] [   ] [   ]   (Welle wandert durch)
LED 7   [   ] [   ] [   ] [   ] [   ] [ ░ ] [ █ ] [ █ ]   (Impulsende)

Eine Indexprüfung verhindert das versehentliche Überlappen über die Ränder des Streifens. Setzt man WAVE_WIDTH = 0, schaltet das System in den klassischen Blinkmodus zurück.

2. Ein-Knopf-Bedienung via internem EEPROM

Da der Arduino Nano über keinen separaten Nutzertaster verfügt, übernimmt der Hardware-Reset-Taster diese Funktion. Der Betriebsstatus wird in EEPROM-Byte 0 hinterlegt:

    ReadEEPROM --> ToggleState: Byte 0 einlesen & Zustand invertieren
    
    state ToggleState <<choice>>
    ToggleState --> StartPlay: Zustand == 1 (Wiedergabe)
    ToggleState --> StopPlay: Zustand == 0 (Stopp)
    
    StartPlay --> ShowGreen: Startsequenz (Rot → Grün → Aus)
    ShowGreen --> EnableTimer: Timer1 COMPA-Interrupt aktivieren

    DisableTimer --> EmptyLoop: loop() bleibt frei

Schutz vor EEPROM-Verschleiß

Das EEPROM des ATmega328P garantiert ca. 100.000 Schreibzyklen. Um unnötige Schreiboperationen zu vermeiden, prüft der Code vor jedem Schreibbefehl if (EEPROM.read(0) != state). Dadurch wird nur geschrieben, wenn sich der Zustand tatsächlich geändert hat.

Vollständiger Quellcode (morse.ino)

Nachfolgend der vollständige, ausführlich dokumentierte Quellcode des Projekts:

// Arduino: Nano Atmel mega328p
// LED: WS2812B (CJMCU-2812-8)
// Used: Timer1 CTC, prescaler 1024, Button interupt

#include <Arduino.h>
#include <Adafruit_NeoPixel.h>    // LED-Ansteuerung
#include <EEPROM.h>               // Persistenter Zustand über Resets hinweg

// Zu übertragende Textnachricht
const char MESSAGE[] = "IN";      ///< Beliebigen Text hier eintragen

// Hardware-Konfiguration
const uint8_t LED_PIN = 6;        ///< Datenpin für den WS2812B-Streifen
const uint8_t WAVE_WIDTH = 5;     ///< 0 = Standard-Blinken, >0 = Leuchtturmeffekt
const uint8_t LED_COUNT = 8;      ///< Anzahl der LEDs auf dem Streifen

// Morse-Timing-Standards (in Millisekunden)
const uint16_t TIME_DOT = 500;          ///< Dauer eines Punkts
const uint16_t TIME_DASH = 1500;        ///< Dauer eines Strichs (3x Punkt)
const uint16_t TIME_SYMBOL_GAP = 500;   ///< Pause zwischen Punkten/Strichen
const uint16_t TIME_LETTER_GAP = 1500;  ///< Pause zwischen Zeichen
const uint16_t TIME_WORD_GAP = 3500;    ///< Pause zwischen Wörtern
const uint8_t BRIGHTNESS = 1;           ///< 1% Helligkeit zur Schonung der Augen

// Instanziierung des NeoPixel-Objekts
Adafruit_NeoPixel led_strip(LED_COUNT, LED_PIN, NEO_GRB + NEO_KHZ800);

// Hardware-Timer1 Kalibrierung (16MHz / 1024 = 15625 Hz)
const uint16_t TICKS_PER_SECOND = 15625;
const uint8_t MAX_STEPS = 100;

// Arrays zur Speicherung der Animationsschritte
uint16_t durations[MAX_STEPS];            ///< Schrittdauer in ms
uint32_t colors[MAX_STEPS];               ///< Schrittfarbe als RGB-Wert
uint8_t ledIndex[MAX_STEPS];              ///< Ziel-LED (255 = alle LEDs)
uint8_t stepCount = 0;
volatile uint8_t currentStep = 0;

/**
 * @brief Zeichentabelle im Flash zur Konvertierung von ASCII in Morsezeichen.
 */
const char* morseCode(char c) {
  switch (c) {
    case 'A': return ".-";   case 'B': return "-..."; case 'C': return "-.-.";
    case 'D': return "-..";  case 'E': return ".";    case 'F': return "..-.";
    case 'G': return "--.";  case 'H': return "...."; case 'I': return "..";
    case 'J': return ".---"; case 'K': return "-.-";  case 'L': return ".-..";
    case 'M': return "--";   case 'N': return "-.";   case 'O': return "---";
    case 'P': return ".--."; case 'Q': return "--.-"; case 'R': return ".-.";
    case 'S': return "...";  case 'T': return "-";    case 'U': return "..-";
    case 'V': return "...-"; case 'W': return ".--";  case 'X': return "-..-";
    case 'Y': return "-.--"; case 'Z': return "--..";
    case '0': return "-----"; case '1': return ".----"; case '2': return "..---";
    case '3': return "...--"; case '4': return "....-"; case '5': return ".....";
    case '6': return "-...."; case '7': return "--..."; case '8': return "---..";
    case '9': return "----.";
    default:  return "";
  }
}

/**
 * @brief Fügt einen Animationsschritt in die Sequenzliste ein.
 */
void addStep(uint16_t duration_ms, uint32_t color, uint8_t ledIdx = 255) {
  if (stepCount < MAX_STEPS) {
    durations[stepCount] = duration_ms;
    colors[stepCount] = color;
    ledIndex[stepCount] = ledIdx;
    stepCount++;
  }
}

/**
 * @brief Kompiliert die Nachricht in Einzelschritte für die LED-Animation.
 */
void buildSequence() {
  stepCount = 0;
  const uint32_t WHITE = led_strip.Color(255, 255, 255);
  const uint32_t OFF = 0;
  
  for (const char* p = MESSAGE; *p; ++p) {
    char c = toupper(*p);
    if (c == ' ') {
      addStep(TIME_WORD_GAP, OFF);
      continue;
    }
    const char* code = morseCode(c);
    if (!*code) continue;

    for (const char* s = code; *s; ++s) {
      uint16_t onDur = (*s == '.') ? TIME_DOT : TIME_DASH;
      uint16_t perLedDur = onDur / LED_COUNT;
      
      // Licht wandert über den Streifen
      for (uint8_t i = 0; i < LED_COUNT; i++) {
        addStep(perLedDur, WHITE, i);
      }
      
      if (*(s + 1)) {
        addStep(TIME_SYMBOL_GAP, OFF);
      }
    }
    addStep(TIME_LETTER_GAP, OFF);
  }
  addStep(TIME_WORD_GAP, OFF);
  
  // Optischer Rücklauf vor dem Wiederholen
  for (uint8_t i = LED_COUNT; i > 0; i--) {
    addStep(20, WHITE, i);
  }
  addStep(TIME_WORD_GAP, OFF);
}

/**
 * @brief Timer1 Compare Match A Interrupt Service Routine.
 * Wird bei jedem Schrittübergang aufgerufen, steuert die LEDs und lädt OCR1A neu.
 */
ISR(TIMER1_COMPA_vect) {
  if (ledIndex[currentStep] == 255 || WAVE_WIDTH == 0) {
    led_strip.fill(colors[currentStep]);
  } else {
    led_strip.clear();
    if (colors[currentStep] != 0) {
      int8_t center = ledIndex[currentStep];
      int8_t halfWidth = WAVE_WIDTH / 2;
      
      for (int8_t offset = -halfWidth; offset <= halfWidth; offset++) {
        int8_t ledPos = center + offset;
        if (ledPos >= 0 && ledPos < LED_COUNT) {
          led_strip.setPixelColor(ledPos, colors[currentStep]);
        }
      }
    }
  }
  led_strip.show();
  
  // OCR1A für die Dauer des nächsten Schritts berechnen
  uint32_t ticks = ((uint32_t)durations[currentStep] * TICKS_PER_SECOND) / 1000UL;
  if (ticks < 100) ticks = 100;
  OCR1A = (uint16_t)(ticks - 1);
  
  currentStep++;
  if (currentStep >= stepCount) {
    currentStep = 0;
  }
}

void showStartupSequence() {
  led_strip.fill(led_strip.Color(255, 0, 0)); led_strip.show(); delay(500);
  led_strip.fill(led_strip.Color(0, 255, 0)); led_strip.show(); delay(500);
  led_strip.fill(0); led_strip.show(); delay(500);
}

void showShutdownSequence() {
  led_strip.fill(led_strip.Color(0, 255, 0)); led_strip.show(); delay(500);
  led_strip.fill(led_strip.Color(255, 0, 0)); led_strip.show(); delay(500);
  led_strip.fill(0); led_strip.show(); delay(500);
}

void setup() {
  led_strip.begin();
  led_strip.setBrightness((255 * BRIGHTNESS) / 100);

  // Status aus dem EEPROM lesen und umschalten
  byte state = EEPROM.read(0);
  state = !state;
  if (EEPROM.read(0) != state) {
    EEPROM.write(0, state);
  }
  
  if (state) {
    showStartupSequence();
    currentStep = 0;
    buildSequence();

    // Timer1 für CTC-Modus mit Prescaler 1024 konfigurieren
    cli();
    TCCR1A = 0;
    TCCR1B = 0;
    TCCR1B |= (1 << WGM12);              // CTC-Modus
    TCCR1B |= (1 << CS12) | (1 << CS10); // Prescaler 1024
    OCR1A = 1562;                        // Startwert ~100ms
    TIMSK1 |= (1 << OCIE1A);             // Compare Match A Interrupt aktivieren
    sei();
  } else {
    showShutdownSequence();
    TIMSK1 &= ~(1 << OCIE1A);            // Interrupt deaktivieren
    TCCR1B = 0;                          // Timer anhalten
  }
}

void loop() {
  // Hauptschleife bleibt zu 100% frei für Hintergrundaufgaben oder Energiesparmodi
}

Technische Erkenntnisse

  1. Deterministisches Timing: Da die Takterzeugung rein über Hardware-Zähler abläuft, führen Programmschleifen oder asynchrone Aufgaben niemals zu Ruckeln oder Signal-Jitter.
  2. ISR-Laufzeit vs. WS2812B-Protokoll: Das Bit-Banging für 8 LEDs benötigt ca. $24\,\text{Bits} \times 8 \times 1{,}25\,\mu\text{s} \approx 240\,\mu\text{s}$. Verglichen mit der kürzesten Intervallpause von 500 ms entspricht dies einem Rechenaufwand von unter 0,05% – absolut unkritisch in der Praxis.
  3. SRAM-Schonung: Durch die Speicherung statischer Zeichentabellen im Flash-Programmspeicher belegt die Sequenztabelle für 100 Schritte nur ca. 700 Bytes des 2048 Bytes großen Arbeitsspeichers.
