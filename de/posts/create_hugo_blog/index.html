Dies ist eine umfassende Schritt-für-Schritt-Anleitung zur Erstellung, Anpassung und Veröffentlichung einer modernen statischen Website mit Hugo und dem cyber-cleanen Smidr-Theme. Ganz gleich, ob der Blog kostenlos auf GitHub Pages gehostet oder vollautomatisiert auf einem eigenen Homeserver betrieben werden soll: Diese Anleitung deckt alle Phasen von der lokalen Einrichtung bis zum produktiven Deployment ab.

Dies ist Teil 1 unserer Hugo-Serie:

  • Teil 1 (Diese Anleitung): Einrichtung, Konfiguration, Smidr-Theme, Leaf Bundles, interaktive Widgets und Veröffentlichung.
  • Teil 2: Hugo auf dem Homeserver via GitHub Actions deployen — automatisiertes Zero-Trust-Deployment hinter Caddy ohne offene SSH-Ports.

Architektur: Wie Hugo und GitHub zusammenspielen

Ein modernes Hugo-Setup ist modular und sauber getrennt:

[Lokaler Desktop]
   ├── Inhalte (Markdown)
   ├── Konfiguration (hugo.yaml)
   └── Themes (Smidr als Git-Submodul)
         │
         ├── (Lokale Vorschau: hugo server unter localhost:1313)
         │
         ▼ (Git Push zum privaten Quell-Repository)
[GitHub: hugo-source]
         │
         ▼ (GitHub Actions Build: hugo --minify)
[Deployment-Ziel]
   ├── Option A: GitHub Pages (https://<username>.github.io)
   └── Option B: Eigener Server / Raspberry Pi via Caddy
  1. Quell-Repository (website bzw. hugo-source): Beherbergt Markdown-Dateien, Entwürfe, Bilder, Konfigurationen und Theme-Submodule. Dieses Repository kann privat sein, um unveröffentlichte Entwürfe zu schützen.
  2. Kompilierte statische Ausgabe (public/): Bei der Ausführung wandelt Hugo Markdown und Vorlagen blitzschnell in statisches HTML, CSS und JavaScript um.
  3. Deployment-Ziel: Wird entweder direkt von GitHub Pages (öffentliches Repository <username>.github.io) ausgeliefert oder von einem eigenen Linux-Server per Automatisierung bezogen.

Voraussetzungen

Vor dem Start sollten die erforderlichen Entwicklungswerkzeuge installiert sein.

1. Terminal

  • Windows: Wir empfehlen PowerShell 7+ anstelle der klassischen Eingabeaufforderung (cmd.exe). Die Installation ist via winget möglich:
    winget install -e --id Microsoft.PowerShell
  • Linux & macOS: Das Standard-Terminal (bash oder zsh) ist direkt einsatzbereit.

2. Git & GitHub

Ein GitHub-Konto sowie eine lokale Git-Installation werden benötigt:

  • Windows:
    winget install -e --id Git.Git
    (Optional: GitHub Desktop via winget install -e --id GitHub.GitHubDesktop für komfortable grafische Anmeldung).
  • Linux (Debian/Ubuntu):
    sudo apt update && sudo apt install git
  • macOS:
    brew install git

Schritt 1: Hugo Extended installieren

💡
Hugo Extended erforderlich
Für das Smidr-Theme wird zwingend die Extended-Version von Hugo benötigt, da diese Hugos Asset-Pipeline für SCSS-Kompilierung, Minifizierung und Fingerprinting nutzt.
  • Windows:
    winget install Hugo.Hugo.Extended
  • macOS (Homebrew):
    brew install hugo
  • Linux: Lade das neueste Extended-Paket (.deb oder Tarball) von den Hugo GitHub Releases herunter:
    hugo version
    Prüfe, ob in der Ausgabe +extended steht (z. B. hugo v0.125.0+extended ...).

Schritt 2: Quell-Repository anlegen

  1. Auf GitHub ein neues privates Repository namens website (oder hugo-source) erstellen.
  2. Ein Terminal öffnen, in das gewünschte Projektverzeichnis wechseln und das leere Repository klonen:
    cd "C:/Projekte" # bzw. ~/Projekte unter Linux/macOS
git clone https://github.com/deinbenutzername/website.git
cd website
  3. Die neue Hugo-Struktur direkt im Ordner initialisieren:
    hugo new site . --force

Schritt 3: Smidr-Theme installieren

Smidr ist ein cyber-cleanes, modernes Hugo-Theme für Ingenieure, Entwickler und Forscher. Wichtige Highlights:

  • Interaktive Code-Ausführung im Browser: Python- und JavaScript-Code direkt via WebAssembly (Pyodide) im Browser ausführen.
  • Zweisprachig / Mehrsprachig: Integrierte Sprachumschaltung mit Seiten-Bundles (.en.md und .de.md).
  • LaTeX / KaTeX Mathematik: Schnelles Rendern komplexer Formeln ( $$E=mc^2$$).
  • Dynamische Filter & Suche: Mehrfachauswahl von Tags und Kategorien mit AND/OR-Logik, Echtzeit-Sortierung und Strg+K-Suche.
  • RSS-Feed mit XSLT-Stylesheet: Schöne, lesbare Feeds im Browser.

Theme als Git-Submodul einbinden:

git submodule add https://github.com/jokobus/smidr.git themes/smidr

Zukünftige Updates des Themes holt man einfach per:

git submodule update --remote --merge

Schritt 4: Konfiguration einrichten

Erstelle oder aktualisiere die Datei hugo.yaml im Hauptverzeichnis (bzw. unter config/_default/hugo.yaml):

baseURL: "https://deinbenutzername.github.io/"
title: "Mein Tech Logbuch"
theme: "smidr"
defaultContentLanguage: "de"
enableRobotsTXT: true

# Multi-Output Konfiguration (erforderlich für Suche & RSS)
outputs:
  home:
    - HTML
    - RSS
    - JSON # Ermöglicht clientseitige Strg+K Schnellsuche
  page:
    - HTML
  section:
    - HTML
    - RSS
  taxonomy:
    - HTML
  term:
    - HTML

# Taxonomien
taxonomies:
  category: "categories"
  tag: "tags"
  archive: "archives"

# Mehrsprachige Konfiguration
languages:
  de:
    label: "Deutsch"
    locale: "de-DE"
    weight: 1
    title: "Mein Tech Logbuch"
    menus:
      main:
        - name: "Start"
          identifier: "home"
          url: "/"
          weight: 10
        - name: "Blog"
          identifier: "posts"
          url: "/posts/"
          weight: 20
        - name: "Über mich"
          identifier: "about"
          url: "/about/"
          weight: 30
        - name: "Kontakt"
          identifier: "contact"
          url: "/contact/"
          weight: 40

  en:
    label: "English"
    locale: "en-US"
    weight: 2
    title: "My Tech Logbook"
    menus:
      main:
        - name: "Home"
          identifier: "home"
          url: "/"
          weight: 10
        - name: "Blog"
          identifier: "posts"
          url: "/posts/"
          weight: 20
        - name: "About"
          identifier: "about"
          url: "/about/"
          weight: 30
        - name: "Contact"
          identifier: "contact"
          url: "/contact/"
          weight: 40

# Goldmark Markdown & KaTeX Parser
markup:
  goldmark:
    renderer:
      unsafe: true
    extensions:
      passthrough:
        enable: true
        delimiters:
          block:
            - ['\[', '\]']
            - ['$$', '$$']
          inline:
            - ['\(', '\)']
            - ['$', '$']
  highlight:
    noClasses: false
    style: "dracula"

Schritt 5: Inhalte mit zweisprachigen Leaf Bundles strukturieren

Die sauberste Organisation für Blogbeiträge in Hugo sind Leaf Bundles. Statt separater Verzeichnisbäume für jede Sprache liegen die Sprachdateien und zugehörigen Bilder gemeinsam in einem Ordner:

content/
├── about.de.md
├── about.en.md
├── contact.de.md
├── contact.en.md
└── posts/
    └── mein-erster-beitrag/
        ├── index.de.md       <-- Deutsche Version
        ├── index.en.md       <-- Englische Version
        └── images/           <-- Beitragsbilder & Grafiken
            └── architektur.svg

1. Neuen Beitrag erstellen

hugo new posts/mein-erster-beitrag/index.de.md

2. Englische Übersetzung ergänzen

Erstelle die Datei index.en.md im selben Verzeichnis und achte darauf, dass beide Dateien denselben Wert für translationKey besitzen:

---
title: "My First Post"
translationKey: "mein-erster-beitrag"
...
---

Hugo und Smidr verknüpfen die beiden Sprachversionen automatisch miteinander, sodass der Umschalter in der Menüleiste sofort funktioniert!

Schritt 7: Lokale Vorschau

Starte den lokalen Hugo-Entwicklungsserver mit Live-Reloading:

hugo server -D

Öffne http://localhost:1313/ im Browser. Änderungen an Markdown-Dateien oder Styles werden innerhalb von Millisekunden live aktualisiert.

Schritt 8: Veröffentlichung des Blogs

Methode A: Automatisiert via GitHub Actions (Empfohlen)

  1. Auf GitHub ein öffentliches Repository namens deinbenutzername.github.io anlegen.
  2. Einen Fine-Grained Personal Access Token mit Schreibrechten für dieses Repository generieren.
  3. Den Token im privaten website-Repository als Secret PUBLIC_REPO_TOKEN hinterlegen.
  4. Die Workflow-Datei .github/workflows/deploy.yml anlegen:
name: Deploy Hugo Site

on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Source & Themes
        uses: actions/checkout@v4
        with:
          submodules: true
          fetch-depth: 0

      - name: Setup Hugo Extended
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: 'latest'
          extended: true

      - name: Build Minified Site
        run: hugo --minify

      - name: Push to GitHub Pages Repository
        uses: cpina/github-action-push-to-another-repository@main
        env:
          API_TOKEN_GITHUB: ${{ secrets.PUBLIC_REPO_TOKEN }}
        with:
          source-directory: 'public'
          destination-github-username: 'deinbenutzername'
          destination-repository-name: 'deinbenutzername.github.io'
          user-email: 'hallo@example.com'
          target-branch: 'main'

Jeder Push ins private Quell-Repository baut und veröffentlicht die Website vollautomatisch in unter einer Minute!

Methode B: Lokales Hilfsskript (Manuelles Publishing)

Für Windows (gitcommit.ps1):

$message = Read-Host "Commit-Nachricht eingeben"
if ([string]::IsNullOrWhiteSpace($message)) { $message = "Website aktualisiert" }

Write-Host "--- 1. Quell-Repository pushen ---" -ForegroundColor Cyan
git add -A
git commit -m $message
git push origin main

Write-Host "--- 2. Statische Ausgabe kompilieren ---" -ForegroundColor Cyan
hugo --minify

Write-Host "--- 3. Deployment-Repository pushen ---" -ForegroundColor Cyan
Set-Location -Path "public"
git add -A
git commit -m $message
git push origin main

Set-Location -Path ".."
Write-Host "Erfolgreich veröffentlicht!" -ForegroundColor Green
