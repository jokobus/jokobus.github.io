Dies ist eine umfassende Schritt-für-Schritt-Anleitung zur Erstellung, Anpassung und Veröffentlichung einer modernen statischen Website mit Hugo und dem cyber-cleanen Smidr-Theme. Ganz gleich, ob der Blog kostenlos auf GitHub Pages gehostet oder vollautomatisiert auf einem eigenen Homeserver betrieben werden soll: Diese Anleitung deckt alle Phasen von der lokalen Einrichtung bis zum produktiven Deployment ab.

💡
Hugo-Publikationsserie

Dieser Artikel ist Teil 1 unserer Hugo- & Smidr-Publikationsserie:

  • Teil 1 (Diese Anleitung): Einrichtung, modulare Konfiguration, Smidr-Theme, Farbpaletten & Farbverlauf, Leaf Bundles und Veröffentlichung.

  • Server-Infrastruktur: Raspberry Pi 4 Homeserver-Anleitung — Caddy-Reverse-Proxy, Nextcloud und containerisierte Dienste.

Architektur: Wie Hugo und GitHub zusammenspielen

Ein modernes Hugo-Setup ist modular, sauber strukturiert und entkoppelt:

[Lokaler Entwicklungs-Rechner]
   ├── Inhalte (Markdown Leaf Bundles in content/posts/)
   ├── Modulare Konfiguration (config/_default/ & optional config/rpi/)
   ├── Eigene Assets (Tailwind CSS, PostCSS)
   └── Themes (Smidr als Git-Submodul)
         │
         ├── (Lokale Vorschau: hugo server -D unter localhost:1313)
         │
         ▼ (Git Push zum privaten Quell-Repository)
[GitHub: hugo-source] (Privates Repository)
         │
         ▼ (GitHub Actions Build: hugo --minify)
[Deployment-Ziel]
   ├── Option A: GitHub Pages (https://<username>.github.io)
   └── Option B: Eigener Server / Raspberry Pi via Caddy (Reverse Proxy)
  1. Quell-Repository (website bzw. hugo-source): Beherbergt Markdown-Dateien, Entwürfe, Bilder, Konfigurationen und Theme-Submodule. Dieses Repository kann privat sein, um unveröffentlichte Entwürfe und interne Einstellungen zu schützen.
  2. Kompilierte statische Ausgabe (public/): Bei der Ausführung wandelt Hugo Markdown, KaTeX-Formeln und Layouts blitzschnell in statisches HTML, CSS und JavaScript um.
  3. Deployment-Ziel: Wird entweder direkt von GitHub Pages (öffentliches Repository <username>.github.io) ausgeliefert oder von einem eigenen Linux-Homeserver per Automatisierung bezogen.

Voraussetzungen

Vor dem Start sollten die erforderlichen Entwicklungswerkzeuge installiert sein:

1. Terminal

  • Windows: Wir empfehlen PowerShell 7+ anstelle der klassischen Eingabeaufforderung (cmd.exe). Die Installation ist via winget möglich:
    winget install -e --id Microsoft.PowerShell
  • Linux & macOS: Das Standard-Terminal (bash oder zsh) ist direkt einsatzbereit.

2. Git & GitHub

Ein GitHub-Konto sowie eine lokale Git-Installation werden benötigt:

  • Windows:
    winget install -e --id Git.Git
    (Optional: GitHub Desktop via winget install -e --id GitHub.GitHubDesktop für komfortable grafische Anmeldung).
  • Linux (Debian/Ubuntu):
    sudo apt update && sudo apt install git
  • macOS:
    brew install git

Authentifiziere deine Git-Installation über einen SSH-Schlüssel oder das GitHub-CLI (gh auth login).

Schritt 1: Hugo Extended installieren

💡
Hugo Extended erforderlich
Für das Smidr-Theme wird zwingend die Extended-Version von Hugo benötigt, da diese Hugos Asset-Pipeline für PostCSS-Kompilierung, Minifizierung und Fingerprinting nutzt.
  • Windows:
    winget install Hugo.Hugo.Extended
  • macOS (Homebrew):
    brew install hugo
  • Linux: Lade das neueste Extended-Paket (.deb oder Tarball) von den Hugo GitHub Releases herunter:
    hugo version
    Prüfe, ob in der Ausgabe +extended steht (z. B. hugo v0.125.0+extended ... oder neuer).

Schritt 2: Quell-Repository initialisieren

Erstelle das zentrale Repository zur Verwaltung deiner Inhalte, Konfigurationen und Assets:

  1. Auf GitHub ein neues privates Repository namens website (oder hugo-source) anlegen.
  2. Terminal öffnen, in das gewünschte Arbeitsverzeichnis wechseln und das leere Repository klonen:
    cd "C:/Projekte" # bzw. ~/Projekte unter Linux/macOS
git clone https://github.com/deinbenutzername/website.git
cd website
  3. Eine neue Hugo-Site direkt im Verzeichnis erzeugen:
    hugo new site . --force
    Hinweis: Der Punkt . sorgt dafür, dass Hugo die Verzeichnisstruktur direkt im geklonten Repository initialisiert.

Schritt 3: Smidr-Theme installieren

Smidr ist ein cyber-cleanes, dunkles Hugo-Theme für Ingenieure, Forschende und Entwickler:

  • WebAssembly-Codeausführung im Browser: Python und JavaScript direkt ohne Backend ausführen (Pyodide).
  • Vollständig zweisprachig: Paralleles Umschalten zwischen Deutsch und Englisch (.de.md und .en.md) über gemeinsamen translationKey.
  • LaTeX / KaTeX-Mathematik: Verzögerungsfreies Rendern komplexer Formeln ( $$\mathcal{L}_{PID}(t)$$).
  • Farbpaletten & „Farbverlauf“: Konfigurierbare Farbschemata mit optionalen leuchtenden Magenta-Violett-Verläufen.
  • Dynamische Sidebar & Suche: Taxonomie-Filter, Sofort-Sortierung und Strg+K / Cmd+K Schnellsuche.
  • Digital Garden & Backlinks: Interaktiver physikalischer Wissensgraph und automatische Rückverweise.
  • RSS-Feeds mit XSLT-Styling: Moderne, dunkle Feeds für Webbrowser und Feed-Reader.

Theme als Git-Submodul einbinden:

git submodule add https://github.com/jokobus/smidr.git themes/smidr

Zukünftige Updates des Themes einspielen:

git submodule update --remote --merge

Schritt 4: Modulare Konfiguration (config/_default/)

Moderne Hugo-Websites nutzen vorteilhafterweise eine modulare Konfigurationsstruktur anstelle einer einzelnen unübersichtlichen Konfigurationsdatei. Wir organisieren die Dateien unter config/_default/:

config/
├── _default/
│   ├── hugo.yaml      <-- Kern-Einstellungen, Menüs, Taxonomien, Markup
│   └── params.yaml    <-- Theme-Parameter, Paletten, Analytics, Features
└── rpi/               <-- Optionale Umgebungs-Überschreibungen (Self-Hosting)
    ├── hugo.yaml
    └── params.yaml

3. Multi-Umgebungs-Architektur (config/rpi/)

💡
Datenschutz & Overrides mit Hugo-Umgebungen
Hugo unterstützt Umgebungen über das --environment-Flag (z. B. hugo --environment rpi). Jede Datei in config/<umgebung>/ überschreibt oder ergänzt die Basis-Konfiguration aus config/_default/.

Um beispielsweise auf dem eigenen Server eine eigene Domain zu nutzen oder private Seiten (wie Impressum mit Klarnamen oder privaten PGP-Schlüsseln) einzubinden, ohne diese im öffentlichen GitHub-Pages-Build zu veröffentlichen, wird config/rpi/hugo.yaml angelegt:

# Überschreibungen für eigene Domain
baseURL: "https://example.com/"
title: "Homeserver Blog"

# Module-Mounts: Sauberes Einbinden zusätzlicher privater Inhalte
module:
  mounts:
    - source: static
      target: static
    - source: static_rpi
      target: static
    - source: content
      target: content
    - source: content_rpi
      target: content
    - source: layouts
      target: layouts

Wird für GitHub Pages gebaut, nutzt hugo --minify die Standardumgebung _default (vollständig anonymisiert). Beim Build für den eigenen Server bindet hugo --minify --environment rpi die privaten Inhalte nahtlos ein!

Schritt 5: Beitragsorganisation mit zweisprachigen Leaf Bundles

Die sauberste Methode zur Beitragsverwaltung in Hugo sind Leaf Bundles. Statt getrennter Sprachordner werden alle Sprachdateien, Bilder und Quellen eines Beitrags gemeinsam in einem Ordner abgelegt:

content/
├── about.de.md
├── about.en.md
├── contact.de.md
├── contact.en.md
└── posts/
    └── mein-erster-beitrag/
        ├── index.de.md       <-- Deutsche Version
        ├── index.en.md       <-- Englische Version
        ├── references.bib    <-- Lokale Bibliografie
        └── images/           <-- Beitragsspezifische Grafiken
            └── architektur.svg

Standard-Archetyp konfigurieren

Damit jeder neue Beitrag automatisch die korrekten Metadaten enthält, wird archetypes/default.md gepflegt:

---
title: "{{ replace .File.ContentBaseName "-" " " | title }}"
description: ""
translationKey: "{{ replace .File.ContentBaseName "-" " " | title | lower }}"
author: "Dein Name"
date: {{ .Date }}
archives: ["{{ dateFormat "2006-01" .Date }}"]
categories: ["Guide"]
tags: []
draft: true
toc: true
---

Neuen Beitrag anlegen

Über das Hugo-CLI das Bündel generieren:

hugo new posts/mein-erster-beitrag/index.de.md

Für die englische Übersetzung index.en.md im selben Ordner anlegen und denselben translationKey verwenden:

---
title: "My First Post"
translationKey: "mein-erster-beitrag"
---

Hugo und Smidr verknüpfen beide Versionen automatisch für den interaktiven Sprachumschalter in der Navigationsleiste!

Schritt 6: Smidr-Shortcodes & Features im Einsatz

Smidr bietet über 20 integrierte interaktive Komponenten für technische Artikel:

  • Python-Ausführung im Browser: Python-Code mit NumPy/SciPy via WebAssembly mit {{< code-runner lang="python" >}}.
  • Interaktive Canvas-Schieberegler: Dynamische Systeme veranschaulichen mit {{< interactive-widget >}}.
  • 3D-Lernkarten (Flashcards): Interaktive 3D-Drehkarten mit {{< flashcard >}}.
  • Periodensystem der Elemente: Interaktives chemisches Periodensystem mit {{< periodic-table >}}.
  • BibTeX-Zitationen & Popovers: Quellen im Text mit {{< cite "schluessel" >}} und Verzeichnis mit {{< bibliography >}}.
  • Cyber-Alerts & Hinweisboxen: 6 Vorlagen (tip, note, warning, caution, info, robotics).
  • Einklappbare Bereiche: Herleitungen übersichtlich verbergen mit {{< collapse >}}.
  • Vektorielle TikZ-Diagramme: Vektordiagramme direkt im Browser mit {{< tikz >}}.
  • Kryptografische Verifikation: PGP-Identität anzeigen mit {{< pgp-card >}}.

Schritt 7: Lokale Vorschau

Starte Hugos Entwicklungsserver für Live-Reloading in Echtzeit:

hugo server -D

Öffne http://localhost:1313/ im Webbrowser. Jede gespeicherte Änderung wird in Millisekunden automatisch neu geladen.

Schritt 8: Veröffentlichung der Website

Es gibt zwei bewährte Methoden zur Veröffentlichung:

Methode A: Automatisierte GitHub Actions CI/CD (Empfohlen)

GitHub Actions kompiliert und deployt die Website automatisch bei jedem Push von neuem Markdown:

  1. Auf GitHub ein öffentliches Repository namens deinbenutzername.github.io anlegen.
  2. Einen Fine-Grained Personal Access Token mit Schreibrechten für deinbenutzername.github.io erzeugen.
  3. Den Token im privaten website-Repository als Secret unter dem Namen PUBLIC_REPO_TOKEN hinterlegen.
  4. Folgenden Workflow in .github/workflows/deploy.yml anlegen:
name: Deploy Hugo Site

on:
  push:
    branches:
      - main

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Quellcode und Themes auschecken
        uses: actions/checkout@v4
        with:
          submodules: true
          fetch-depth: 0

      - name: Hugo Extended installieren
        uses: peaceiris/actions-hugo@v3
        with:
          hugo-version: 'latest'
          extended: true

      - name: Website minifiziert bauen
        run: hugo --minify

      - name: In GitHub-Pages-Repository übertragen
        uses: cpina/github-action-push-to-another-repository@main
        env:
          API_TOKEN_GITHUB: ${{ secrets.PUBLIC_REPO_TOKEN }}
        with:
          source-directory: 'public'
          destination-github-username: 'deinbenutzername'
          destination-repository-name: 'deinbenutzername.github.io'
          user-email: 'kontakt@example.com'
          target-branch: 'main'

Methode B: Lokales Automatisierungs-Skript (Manuelles Deployment)

Wer lokal kompilieren und manuell deployen möchte, nutzt ein PowerShell-Hilfsskript (git_commit.ps1):

$message = Read-Host "Commit-Nachricht eingeben"
if ([string]::IsNullOrWhiteSpace($message)) { $message = "Blog aktualisiert" }

Write-Host "--- 1. Quell-Repository pushen ---" -ForegroundColor Cyan
git add -A
git commit -m $message
git push origin main

Write-Host "--- 2. Statische Ausgabe kompilieren ---" -ForegroundColor Cyan
hugo --minify

Write-Host "--- 3. Deployment-Repository pushen ---" -ForegroundColor Cyan
Set-Location -Path "public"
git add -A
git commit -m $message
git push origin main

Set-Location -Path ".."
Write-Host "Website erfolgreich deployt!" -ForegroundColor Green

Schritt 9: Crawler, SEO & RSS-Feeds

1. Robots.txt

Bei enableRobotsTXT: true generiert Hugo die Datei automatisch. Um Suchmaschinen-Crawler vollständig auszusperren, genügt layouts/robots.txt:

User-agent: *
Disallow: /

Smidr bringt ein XML-Stylesheet (static/rss-style.xsl) mit. Beim Aufruf von /index.xml im Browser erscheint ein aufgeräumter Cyber-Feed statt unformatiertem XML.
