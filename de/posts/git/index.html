Git & GitHub: Das ultimative Praxishandbuch

“Git ist ein freies System zur verteilten Versionsverwaltung von Dateien, das meist zur Versionsverwaltung von Quellcode während der Softwareentwicklung eingesetzt wird.” — Wikipedia

I. Einrichtung & Konfiguration

1. Git installieren

Überprüfe im Terminal mit git --version, ob Git bereits vorhanden ist.

  • Windows:
    winget install --id Git.Git -e --source winget
  • macOS:
    brew install git
  • Linux:
    # Debian, Ubuntu, Raspberry Pi OS
sudo apt install git

# Arch Linux
sudo pacman -S git

# Fedora
sudo dnf install git

2. GitHub CLI (gh) installieren

Sehr empfehlenswert für Pull Requests und Repository-Verwaltung direkt aus dem Terminal:

  • Windows: winget install --id GitHub.cli
  • macOS: brew install gh
  • Linux: sudo apt install gh oder sudo pacman -S github-cli

Authentifizierung:

gh auth login

3. Grundkonfiguration (Identität setzen)

git config --global user.name "Dein Name"
git config --global user.email "deine.email@example.com"
💡
Tipp für separate Projekt-Identitäten
Lässt du das Flag --global weg, gilt die Konfiguration ausschließlich für das aktuelle Repository im jeweiligen Ordner.

4. SSH-Authentifizierung einrichten

Empfohlen für sicheren, passwortlosen Zugriff:

  1. Schlüssel erzeugen:
    ssh-keygen -t ed25519 -C "deine.email@example.com"
  2. Standardpfad bestätigen (mit Enter).
  3. Schlüssel zum SSH-Agenten hinzufügen:
    ssh-add ~/.ssh/id_ed25519
  4. Öffentlichen Schlüssel bei GitHub hinterlegen: Den Inhalt von id_ed25519.pub kopieren und unter GitHub Settings $\rightarrow$ SSH and GPG keys einfügen.
  5. Verbindung testen:
    ssh -T git@github.com

II. Lokale Git-Grundlagen

Repository initialisieren

git init

Status & Änderungen einsehen

  • git status: Zeigt den Status von Staging-Area und Arbeitsverzeichnis.
  • git diff: Zeigt konkrete Änderungen an noch nicht gestagten Dateien.
  • git diff --staged: Zeigt Änderungen, die für den nächsten Commit vorgemerkt sind.

Änderungen stagen (git add)

git add datei.txt   # Einzelne Datei stagen
git add .           # Alle Änderungen im aktuellen Ordner stagen
git add -A          # Alle Änderungen im gesamten Repository (inkl. Löschungen) stagen

Commits erstellen

git commit -m "Sprechende Beschreibung der Änderung"

Verlauf & Hilfe

  • git log --oneline --graph --all: Übersichtliche grafische Baumansicht aller Branches.
  • git log -5: Zeigt die letzten 5 Commits.
  • git <befehl> --help: Zeigt die offizielle Dokumentation zu einem Befehl.

Branching (Zweige erstellen)

# Neuen Branch erstellen und direkt dorthin wechseln
git checkout -b feature-neue-funktion

# Änderungen committen
git add -A
git commit -m "Implementiere neue Funktion"

# Zurück zu main und mergen
git checkout main
git merge feature-neue-funktion

# Temporären Branch nach erfolgreichem Merge löschen
git branch -d feature-neue-funktion

III. GitHub-Integration & Remotes

⚠️
Wichtigste Grundregel
Halte deinen lokalen Stand stets aktuell (git pull origin main). Wer auf veralteten Ständen weiterarbeitet, riskiert unnötig komplexe Merge-Konflikte!

Remote verbinden

# Klonen eines bestehenden Repositories via SSH
git clone git@github.com:benutzername/repository.git

# Oder ein bestehendes lokales Repo mit GitHub verbinden:
git remote add origin git@github.com:benutzername/repository.git
git push -u origin main

IV. Nützliche Werkzeuge & Fehlerbehebung

Änderungen zwischenspeichern (git stash)

Wenn du spontan den Branch wechseln musst, ohne unfertige Arbeit zu committen:

git stash save "Zwischenstand Feature X"
git stash list
git stash pop

Fehler rückgängig machen

  • Datei auf letzten Stand zurücksetzen: git checkout -- dateiname
  • Letzte Commit-Nachricht korrigieren: git commit --amend -m "Korrigierter Text"
  • Sicheres Rückgängigmachen per neuem Commit: git revert HEAD
  • Lebensretter bei verlorenen Commits: git reflog

Remote-Branch auf GitHub löschen

git push origin --delete branchname

# Lokale verwaiste Verweise bereinigen:
git fetch origin --prune
