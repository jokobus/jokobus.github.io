Lokale KI mit Ollama, Open-WebUI und VSCode/VSCodium betreiben

📅 30. Jun 2026 ⏱️ ~4 Min. Lesezeit (718 Wörter) #Ollama #IDE #VSCode #VSCodium #Künstliche Intelligenz #Datenschutz

Dieser Leitfaden führt dich Schritt für Schritt durch die Installation von Ollama auf einem Linux-System, die Bereitstellung über ein rein lokales Open-WebUI (ohne Freigabe ins Internet) und die nahtlose Anbindung deiner lokalen Sprachmodelle (LLMs) als KI-Coding-Assistent und Autocomplete-Engine in VSCode bzw. VSCodium.

💡
Vorteile einer 100% lokalen KI-Infrastruktur
  • Keine Root-/Sudo-Rechte erforderlich: Läuft vollständig im User-Space deines Home-Verzeichnisses.
  • 100% Datenschutz & Air-Gapped: Null Telemetrie, kein Scraping durch Drittanbieter – alle Inferenz-Daten bleiben strikt auf localhost.
  • Kostenfrei & Unbegrenzt: Keine monatlichen API-Abonnements oder Token-Limits.
  • Erweiterbarkeit mit Websuche: Open-WebUI kann optional an Suchmaschinen (z. B. SearXNG oder DuckDuckGo) für Live-RAG (Retrieval-Augmented Generation) angebunden werden.

Hardware-Voraussetzungen

  • Hardware-Beschleunigung: Während leichtgewichtige quantisierte Modelle (1B–3B Parameter) problemlos auf modernen Mehrkern-CPUs laufen, entfalten 7B+-Modelle und interaktive Code-Vervollständigung ihr volles Potenzial auf dedizierten Grafikkarten mit mindestens 8 GB VRAM (NVIDIA CUDA, AMD ROCm oder Apple Silicon Unified Memory).
  • Betriebssystem: Dieser Guide fokussiert sich auf Entwickler-Setups unter Linux (Ubuntu, Debian, Fedora, Arch). Native Installer stehen auch für Windows und macOS bereit.

1. Ollama installieren

Verzeichnisstruktur anlegen

Zunächst erstellen wir eine saubere, isolierte Verzeichnisstruktur im eigenen Home-Verzeichnis:

mkdir -p ~/ollama/{bin,lib,logs,models,webui}
  • bin/: Beherbergt die ausführbare Ollama-Binärdatei.
  • lib/: Zusätzliche Bibliotheken und Abhängigkeiten.
  • logs/: Protokolldateien für Server und Hintergrundprozesse.
  • models/: Speicherort für heruntergeladene LLMs (z. B. Qwen, Llama, Mistral).
  • webui/: Speicherort für Web-Frontend-Dateien.

Binärdatei herunterladen und ausführbar machen

# Aktuelle Linux-Binärdatei direkt herunterladen
curl -L https://ollama.com/download/ollama-linux-amd64 -o ~/ollama/bin/ollama

# Ausführungsrechte vergeben
chmod +x ~/ollama/bin/ollama

Umgebungsvariablen konfigurieren

Öffne deine Shell-Konfiguration:

nano ~/.bashrc

Füge am Dateiende folgende Zeilen ein:

export PATH=~/ollama/bin:$PATH
export LD_LIBRARY_PATH=~/ollama/lib:$LD_LIBRARY_PATH
export OLLAMA_MODELS=~/ollama/models

Speichere die Datei (Strg+O, dann Enter, dann Strg+X) und lade die Umgebung neu:

source ~/.bashrc

Ollama-Server starten & Modell herunterladen

# Server im Hintergrund starten
nohup ollama serve > ~/ollama/logs/server.log 2>&1 &

# Modell herunterladen und testen (z. B. Qwen 2.5 Coder 7B oder 30B)
ollama run qwen2.5-coder:7b
📝
Note
Der Download größerer Modelle nimmt je nach Internetbandbreite etwas Zeit in Anspruch. Nach Abschluss kannst du direkt im Terminal Fragen stellen und den Prompt anschließend mit /exit verlassen.

2. Open-WebUI installieren

Für eine moderne, ansprechende Browser-Oberfläche im Stile von ChatGPT unter http://localhost:8080 installieren wir das quelloffene Open-WebUI.

Conda-Umgebung erstellen (Empfohlen)

conda create --name ollama_webui python=3.11 -y
conda activate ollama_webui
conda install pip -y

Paket installieren und starten

python -m pip install open-webui
open-webui serve

Öffne deinen Browser unter http://localhost:8080 und erstelle deinen initialen Administrator-Account. Da der Dienst komplett lokal läuft, verlassen deine Zugangsdaten niemals deinen Rechner. Wähle dein Modell im Dropdown-Menü aus und starte deinen ersten Prompt.

3. Autostart beim Systemstart automatisieren

Um nicht nach jedem Rechnerneustart mehrere Befehle manuell absetzen zu müssen, bündeln wir den Start in einem Shell-Skript:

nano ~/ollama/start_ollama_webui.sh

Füge folgendes Skript ein:

#!/bin/bash

# 1. Umgebungsvariablen laden
source ~/.bashrc

# 2. Ollama im Hintergrund starten, falls noch nicht aktiv
if ! pkill -0 ollama; then
    nohup ollama serve > ~/ollama/logs/ollama.log 2>&1 &
    sleep 3
fi

# 3. Open WebUI strikt an localhost binden
export HOST=127.0.0.1
export PORT=8080

# Conda für Subshell initialisieren (Pfad ggf. anpassen: miniforge3 / miniconda3)
eval "$($HOME/miniforge3/bin/conda shell.bash hook)"

conda activate ollama_webui
nohup open-webui serve > ~/ollama/logs/ollama_webui.log 2>&1 &

echo "Ollama und Open-WebUI erfolgreich im Hintergrund gestartet!"

Skript ausführbar machen:

chmod +x ~/ollama/start_ollama_webui.sh

Als Cronjob (@reboot) eintragen

crontab -e

Füge folgende Zeile am Ende der Datei ein:

@reboot ~/ollama/start_ollama_webui.sh

Damit startet deine persönliche KI-Zentrale nach jedem Bootvorgang lautlos im Hintergrund.

4. Anbindung an VSCodium / VSCode mit “Continue”

Standard-Erweiterungen wie GitHub Copilot erfordern oft externe Cloud-Logins. Die erstklassige Open-Source-Erweiterung Continue erlaubt den vollständigen Offline-Betrieb.

Erweiterung installieren

  1. Öffne VSCodium / VSCode und wechsle in die Erweiterungsansicht (Strg+Umschalt+X).
  2. Suche nach Continue.
  3. Klicke auf Installieren.

Continue-Konfiguration (config.yaml)

Klicke in der Seitenleiste auf das Continue-Symbol und unten auf das Zahnrad-Symbol, um die Konfigurationsdatei config.yaml zu bearbeiten:

name: VSCodium Setup
version: 1.0.0
schema: v1

disableIndexing: false
ignoreRules:
  - "../**"
  - "**/node_modules/**"
  - "**/.git/**"
  - "**/__pycache__/**"
  - "*.env"

models:
  # Erkennt alle via Ollama installierten Modelle automatisch
  - name: Ollama Autodetect
    provider: ollama
    model: AUTODETECT
    roles:
      - chat
      - edit
      - apply
    requestOptions:
      timeout: 300

  # Schnelle Inline-Codevervollständigung (Ghost Text beim Tippen)
  - name: Qwen 2.5 Coder 7B (Autocomplete)
    provider: ollama
    model: qwen2.5-coder:7b
    roles:
      - autocomplete

tabAutocompleteOptions:
  debounceDelay: 100
  maxPromptTokens: 2048
💡
Optionale Gemini-Einbindung
Falls du zusätzlich extrem leistungsfähige Cloud-Modelle (wie Gemini 2.5 Pro / Flash) für komplexe Aufgaben nutzen möchtest, kannst du deinen kostenfreien API-Key von aistudio.google.com eintragen. Beachte dabei, dass diese Anfragen nicht mehr lokal bleiben.
